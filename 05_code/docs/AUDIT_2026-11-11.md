# Независимый разбор: что работает и что найдено

Дата: 11 ноября 2026. Это аудит исследовательского прототипа, не формальная сертификация безопасности и не доказательство качества рекомендаций.

## Что реализовано

Импорт PostgreSQL backup в локальную SQLite без исполнения SQL из записей; фильтрация публикации и доступа; каталог и темы; ограниченно доступные тексты статей и уроков; лексический BM25 по полям и dense-поиск по фрагментам; объединение через RRF; подсказки и уточнения; локальный интерфейс; отдельные тесты и экспериментальный CatBoost. Пользовательские запросы внешним LLM не отправляются. В каталоге 1 469 карточек; сайт Альфа-Курс новее или отличается, например отсутствуют две карточки безопасной разработки Frontend и Backend — причина различия не установлена.

## Подтверждённые проблемы и исправления

1. **Некорректная сопоставимость старых экспериментов.** CatBoost измерялся на кандидатах с подобранными весами, приложение использовало исходные. `scripts/experiments.py` исправлен: CatBoost и baseline получают одинаковые исходные параметры. Старый отчёт не переписан; исправленный хранится в `evaluation/results_corrected/`.
2. **Название метрики вводило в заблуждение.** Прежнее `recall60_judged` считалось после ранжирования, а не на начальном объединённом пуле, который может содержать до 120 кандидатов. Его следует читать как ранжированный recall@60; отдельный синтетический тест считает candidate recall до перестановки. При сравнении старых отчётов учитывать это.
3. **Слишком мало ручных суждений.** 58 запросов, 4 оценки на запрос, около 25% судимых результатов в top-5. Остальные ошибочно трактуются как 0 в pooled NDCG. Исходная test-часть уже наблюдалась. Добавлен независимый по исходным карточкам слабый набор 2 008 синтетических запросов с разделением по документам, но он сам по себе не заменяет ручную разметку. [Данные и результаты](../evaluation/large_results/README.md).
4. **Неопределённость целостности модели.** Новый локальный embedding-индекс сохраняет fingerprint весов и tokenizer; при его наличии файлы повторно проверяются. CatBoost привязан к SHA-256 каталога, векторов и собственному файлу, список признаков сопоставляется с моделью. Проверка конфигурации ранжирования также требует совпадения с каталогом. Ранее созданные старые индексы без fingerprint в целях совместимости остаются без этой проверки.
5. **Пять признаков вместо полного набора.** Обучена отдельная экспериментальная модель с пятью признаками и добавлена в UI. Её коэффициенты и имена проверяются, выходной скор показывается в режиме исследования. При выборе уточнения применяется тот же ограниченный boost, что и раньше; эта часть отдельно не размечена и не настроена.
6. **Дублирование BM25 и лишние вычисления.** Старая функция `cli.bm25` сохранена для совместимости как обёртка над единой реализацией `BM25Index`; повторное токенизирование тем/тегов/отраслей на каждый запрос заменено кешированием. Индекс продолжает использовать отдельные поля.
7. **Проверки.** Добавлены тесты разбиения synthetic, отдельных candidate recall/ranking, fingerprint, несовместимого конфига и проверки малой модели/повреждения артефакта. При отсутствии optional CatBoost/NumPy эти тесты корректно пропускаются. Ruff, выбранные security-правила и проверка синтаксиса JS выполнены.

## Не исправлено и что делать дальше

- **Нет крупной независимой оценки.** Собрать настоящие анонимизированные формулировки запросов либо самостоятельно сформулировать разнообразные задачи без копирования текста карточек; разметить достаточно широкий объединённый пул хотя бы двумя людьми и выделить до экспериментов непросмотренный test. Проверять разногласия и межэкспертное согласие. Если реальных запросов нет, не выдавать искусственно сгенерированные за логи.
- **Синтетические данные слишком легки.** В test MRR@10 около 0.996 после ranker на извлечённых фрагментах документов. Такой результат не является 99% качества для людей. Пять признаков по старым примерам 0.602 против 0.610 baseline, но низкое покрытие разметки и наблюдавшаяся выборка не доказывают различия. Приоритет — улучшить оценку, а не автоматически переключить модель.
- **Нет надёжного определения отсутствия ответа.** Dense-канал возвращает ближайшие векторы даже на несвязанный запрос. `coverage=unknown` — не проверка достаточной релевантности. Нужны размеченные отсутствующие темы и калибровка, а не произвольный порог cosine.
- **Нет пользовательских сигналов и дохода.** История не означает показы или покупки; конверсию и выгоду нельзя обучить по выдуманным признакам. Для персонализации потребуются подтверждённые события и раздельная оценка offline/online.
- **Каталог неполон, ссылки и доступ не подтверждены.** Не все относительные slug превращены в ссылки, тарифы/цены могут быть неизвестны. Пробный статус и открытый тип в исходной базе не являются проверкой прав конкретного человека. Перед интеграцией нужны проверенный источник каталога, права и политика использования.
- **Подсказки и опечатки эвристические.** Нет полноценной русской морфологии или смыслового уточнения намерения. Дополнительные темы извлекаются по совместным материалам, LLM не подключена. Часть формулировок может быть неудачной.
- **Длинные материалы.** Max pooling по всем фрагментам даёт длинной статье больше шансов на высокую похожесть; число фрагментов пока не калибруется. Нужны сравнение и latency/load test на отдельном наборе.
- **Concurrency и модель.** Запись индекса и метаданных разделена на несколько файлов; контрольные суммы предотвращают незаметную порчу, но при одновременном чтении и обновлении возможна временная ошибка. Не обновлять embedding-индекс при запросах; требуется атомарная публикация отдельного поколения. Fingerprint проверяется для локальной модели, когда он сохранён; старые индексы и загрузка по удалённому ID нужно мигрировать к полной проверке содержимого и версий библиотек.
- **Инфраструктура.** Локальный HTTP-сервер только для разработки и не включает полноценную защиту публичного сервиса, авторизацию, лимиты и контроль нагрузки. Нативное восстановление PostgreSQL в Docker ещё не было проверено запуском. Не публиковать дамп/векторы/запросы в открытом Git.
- **Подсказка и категория не сильнее задачи.** Boost ограничен, но не оценивался на достаточном числе размеченных выборов; `selection_match` в старом обучении был постоянным нулём. Для новой модели с пятью признаками уточнение действует отдельно после ранжирования. Оценить руками и отдельным тестом.

## Как проверить

Из `05_code`: `PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v`, `ruff check src tests scripts`, `ruff check src --extend-select S`, `ruff format --check src tests scripts`. Для обучения крупного синтетического эксперимента — команда в [отчёте](../evaluation/large_results/README.md). В браузере запустить `Запустить демо.command`, выбрать `CatBoost · 5 признаков`; baseline остаётся `По словам и смыслу`. Оценки моделей не вероятности покупки. Доступ только локальный.
