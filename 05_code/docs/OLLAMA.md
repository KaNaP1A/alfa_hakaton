# Локальная Gemma и обработка запроса

В предыдущем прогоне на этом Mac была установлена `gemma3:1b`. Этот аудит выполнялся без LLM и не проверял, запущена ли сейчас Ollama. Для запуска интерфейса откройте `Запустить демо.command` или выполните из `05_code`:

```bash
PYTHONPATH=src .venv/bin/python -m alfa_reco serve --hybrid --open-browser --port 8002
```

Оставьте окно Terminal открытым. Если порт занят, откройте уже работающий интерфейс либо выберите другой порт. При необходимости включите приложение Ollama или выполните `ollama serve` в отдельном окне. Список моделей: `ollama list`. Если переносите проект на другой Mac без этой модели, установите её командой `ollama pull gemma3:1b`. API-ключ не нужен.

После нажатия «Найти» короткие и сложные запросы отправляются только локальному сервису `127.0.0.1:11434` в режиме JSON. Подсказки при вводе работают без вызова LLM. Маршрутизация использует длину запроса и наличие отрицаний; это эвристика, а не точная классификация сложности. Обычные запросы проходят без модели.

Gemma предлагает действие, предмет и явно названные условия. Из каждого поля оставляются лишь точные фрагменты исходного запроса; для отдельного русского слова допускается проверенная форма того же слова и возвращается слово пользователя. Поэтому выдуманные слова исключаются, но совпадение с текстом **не доказывает, что фрагмент извлечён в правильном смысле**. При отсутствии сервиса, занятой модели, ошибке и неподтверждённом ответе поиск продолжится по исходному тексту. Ожидание сервиса ограничено, запросы на разбор не накапливаются в очереди; результаты хранятся в памяти не более пяти минут. Не отправляйте конфиденциальные данные в локальный демонстрационный интерфейс.

Модель не создаёт теги каталога, не переформулирует запрос для поиска и не придумывает фильтры. При ненулевом подобранном коэффициенте проверенный предмет может слегка повысить уже найденные материалы, в заголовке или описании которых совпадают слова предмета. При наличии отрицания LLM-бонус полностью отключён. Для явных противопоставлений вроде «сотрудников, а не клиентов» отдельное правило понижает заголовки с исключённым словом; оно не гарантирует правильного разбора отрицаний. Другие условия вроде бесплатности пока автоматически не фильтруются. Вывод разбора и влияние на ранжирование — разные вещи: если тесты выбрали коэффициент ноль, разбор виден, но порядок не меняется.

Интеграцию можно отключить флагом `--no-llm`. Чтобы пересчитать веса и проверить фактическую модель локально:

```bash
PYTHONPATH=src .venv/bin/python scripts/ensemble_experiment.py --with-ollama --install
PYTHONPATH=src .venv/bin/python scripts/evaluate_ollama.py
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v
```

`--install` меняет активные веса: перезапустите сервер для проверки. Прежде чем сравнивать прогоны, учитывайте версию каталога и модели, synthetic-разметку и ограниченную полноту оценок. Результаты извлечения сохраняются в `evaluation/ollama_results/report.json`, а детальный отчёт подбора — в `evaluation/ensemble_results_v2/`. См. также [документацию Ollama о структурированных ответах](https://docs.ollama.com/capabilities/structured-outputs).
