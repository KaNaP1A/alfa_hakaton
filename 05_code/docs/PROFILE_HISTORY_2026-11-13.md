# Профиль и история для алгоритма

Это Python-интерфейс алгоритма, а не новое HTTP API. Текущие `/search`, `/recommend` и `/development-plan` сохраняют старый контракт. Бэкенд может отдельно вызвать функции ниже после интеграции, передав профиль из доверенного хранилища. Авторизация, проверка событий, актуальной публикации и прав — ответственность бэкенда.

## Формат профиля

```json
{
  "generation": "поколение каталога",
  "goal": "хочу разобраться с управлением сотрудниками",
  "business_stage": "operating",
  "industry": "Торговля",
  "region": "Москва",
  "experience": "beginner",
  "allow_revisit": false,
  "preferred_kinds": ["webinar", "course"],
  "categories": ["team"],
  "focus_facet": "Управление командой",
  "events": [
    {"entity_key": "course:идентификатор", "action": "viewed"},
    {"entity_key": "course:идентификатор", "action": "started"}
  ]
}
```

Обязателен `generation`, совпадающий с поколением каталога движка. Прочие поля можно опустить; `goal`, `industry`, `business_stage`, `experience` также принимают `null`. Непустая цель — строка длиной до 300 символов. Стадии: `idea`, `launch`, `operating`, `scaling`; опыт: `beginner`, `intermediate`, `advanced`. Сфера сопоставляется с `industries` без учёта регистра и с небольшим явным списком синонимов: например, «ритейл» → «Розница», `e-commerce` → `ECom`, `HoReCa` учитывает похожую кириллическую букву в источнике. Произвольного семантического сопоставления нет. Метки «Без опыта» и «С опытом» не считаются отраслями. Предпочитаемые типы: `article`, `course`, `document`, `podcast`, `webinar`, `calculator`. Интересы: `business`, `finance`, `team`, `marketing`, `technology`.

`events` — максимум 50 явно переданных событий, от старого к новому. У каждого ровно `entity_key` материала текущего поколения и `action`: `viewed` — просмотр, `interested` — явно выраженный интерес, `started` — начат курс, `completed` — завершён курс. Два последних действия принимаются только для типа `course`. Начало, просмотр и интерес не считаются завершением, покупкой или освоением. Для повторов сохраняется наиболее сильное из явно переданных действий, позиция определяется последним появлением; даты не выдумываются. Обрабатываются до 20 последних уникальных материалов истории. Начатые и завершённые курсы исключаются из рекомендаций по идентификатору; явный `allow_revisit: true` разрешает их повторный подбор. В плане развития материалы из истории по-прежнему исключаются: этот флаг относится только к рекомендациям. Одинаковое название само по себе больше не доказывает, что разные идентификаторы являются дублями.

Для уточнения цели поддерживаются необязательные `clarification_token` либо `clarification_text`, но не одновременно и только при наличии `goal`. Токен выдаётся исходным поиском, привязан к исходному тексту и поколению и действует только в том же процессе. При устаревшем токене нужно повторить поиск.

Необязательный `focus_facet` должен точно соответствовать одной из фактических меток выбранной категории; варианты выдаёт `onboarding` для выбранных категорий. Он строго ограничивает основные результаты и шаги плана, может привести к пустой выдаче и не фильтрует отдельные альтернативы исходного поиска. Необязательный `region` — строка до 150 символов; в холодном старте он используется только для непроверенных подсказок по отдельным упоминаниям городов в заголовках. При цели или истории регион на ранжирование не влияет, что видно в `profile_usage`. Подробности и ограничения — в [описании холодного старта](COLD_START_2026-11-13.md).

## Вызов из Python

```python
from alfa_reco.profile import recommend_for_profile, development_plan_for_profile
from alfa_reco.search import SearchEngine

engine = SearchEngine("artifacts/catalog")
profile = {
    "generation": engine.generation,
    "goal": "управление сотрудниками",
    "preferred_kinds": ["webinar"],
    "categories": ["team"],
    "events": [],
}
recommendations = recommend_for_profile(engine, profile, limit=5)
plan = development_plan_for_profile(engine, profile)
```

При ненулевой истории можно передать обеим функциям `vectors=engine.relevance_backend().vectors["card"]`, если бэкенд загрузил совместимую модель: связи истории тогда учитывают существующий семантический канал. Если векторы не переданы, используются лексика и подтверждённые темы/теги. Профиль и события должны быть проверены бэкендом; сам алгоритм не проверяет, действительно ли пользователь выполнил действие.

## Как учитываются данные

- При наличии цели `recommend_for_profile` берёт только `results` основного поиска `relevance` (до 50 кандидатов), не добавляя материалы из истории или категорий вне выдачи. Идентификаторы и дубли проверяются. История, совпадающие категория, сфера, формат и найденные признаки стадии/опыта лишь перераспределяют этот список. По умолчанию начатые/завершённые курсы исключаются по ID. При отсутствии результатов выдача пустая.
- Без цели и истории выбранные категории обрабатываются алгоритмом [холодного старта](COLD_START_2026-11-13.md); без категории возвращается необязательный вопрос `onboarding`. При наличии истории источником кандидатов служит существующая контентная связь или выбранные категории. Одна только сфера или формат не создают подборку без тематического сигнала. Отбор по сфере и формату мягкий, не жёсткий фильтр: неподтверждённая сфера не придумывается и не исключает материал.
- Для каждого результата `profile_evidence` содержит первоначальную позицию по цели (`goal_rank`), признаки совпадения формата, сферы и категории, источник стадии/опыта при совпадении, а также ID и действие источника истории, если оно повлияло. Исходный `scores.final_score`, если присутствует, не пересчитывается; итоговый порядок — порядок массива. При отсутствии сформированного контекста возвращается `insufficient_evidence`.
- В `goal_search` сохраняются `confidence`, `clarification`, `focus`, `coverage`, `query_rules`, `notice` и альтернативы исходного поиска. Альтернативы не персонализированы и остаются отдельными от основных результатов; начатые/завершённые курсы исключаются из них по ID, если `allow_revisit` не включён. Неопределённость поиска не скрывается: при результатах и `confidence.status=uncertain` или неподтверждённых ограничениях общий статус рекомендаций — `uncertain`. Для плана с шагами исходный статус остаётся в `plan_status`, а общий становится `uncertain`. Если цель не задана, `goal_search` равен `null`.
- `development_plan_for_profile` строит шаги по содержательной связи с историей. Если задана цель, шаги дополнительно ограничены кандидатами поиска по ней. Действия различаются в `evidence.signal` и в тексте; материалы из истории исключаются по ID, но совпадение названий не доказывает дубль. План может быть пустым, если подтверждённых связей недостаточно. Входные формат и сфера дают мягкое предпочтение только подходящим кандидатам.
- Стадия и опыт используются только при узком совпадении с данными источника. Метка `industries: «Без опыта»` сопоставляется с `beginner`, а `«С опытом»` — с `intermediate` и `advanced` как общий признак наличия опыта, **не как доказательство продвинутого уровня темы**. Противоречивые метки игнорируются. Для стадии `launch` распознаётся только явно адресованная фраза «вы только начинаете бизнес» в `Courses.Target`; это буквальное правило, а не стандартизованная разметка. Другие свободные описания и неподтверждённые значения остаются неизвестными. Источник и тип совпадения отражаются в `profile_evidence` / `profile_matches`; `profile_usage` показывает `used_when_source_matched`, `no_catalog_match` или `not_provided`.

## Ограничения качества

Поправки эвристические: для совпадения формата, сферы и категории в подборке используются множители 1,1; соответствие истории добавляет не более 15% к исходному весу позиции; явные подсказки стадии и опыта дают по 1,05. Для плана формат и сфера дают множитель 1,1, стадия и опыт — 1,05. Это не обученные и не калиброванные веса. Для активности заданы инженерные относительные веса от просмотра до завершения и убывание по порядку и позиции связанного материала. Отсутствие семантических векторов меняет используемый метод. Методика и проверки не доказывают персональную полезность, успешное обучение или рост конверсии.

Действующий каталог содержит 1125 допускаемых карточек; поле `industries` заполнено у 194, но в нём смешаны отрасли и другие фасеты. Из них 169 имеют отраслевую или рыночную метку, ещё 25 — только метки опыта или служебную метку. Явная метка «Без опыта» есть у 19 курсов, «С опытом» — у 4; прямой фразе о начале бизнеса соответствует одна карточка. Это очень неполное покрытие, а текстовое правило не заменяет проверенную стандартизованную разметку. Из-за этого пункт 4 реализован **частично**: полноценное ранжирование по стадии и уровню требует более полных проверенных метаданных и проверки на пользовательских сценариях.

На существующих размеченных вопросах проведена [диагностика влияния профиля](PROFILE_DIAGNOSTIC_2026-11-13.md). При сочетании искусственно заданных предпочтений общая релевантность запроса на сопоставимом подмножестве немного снизилась; оценки соответствия предпочтениям в наборе отсутствуют, поэтому улучшение персонализации не доказано.
