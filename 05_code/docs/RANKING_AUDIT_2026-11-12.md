# Аудит поиска, BM25, кода и данных для ML

12 ноября 2026. Проверена локальная реализация и доступные артефакты. Основной вывод: BM25 математически корректен и детерминирован; подобранный кандидат не обобщился на отложенную часть. Наиболее заметны недостатки обработки смысла и ограничений допуска, а не ошибка формулы. Независимого доказательства качества для пользователей пока нет.

## Что выполнено

- Исходные 114 тестов прошли. После исправлений — **133 теста**, включая HTTP API, независимый расчёт формулы BM25, границы параметров, насыщение, длину, пустые поля, повтор термов, перестановки, 5000 документов, совместимость моделей и метрики.
- Через настоящий `SearchEngine.search` проверены четыре режима на **193 запросах / 45 семействах**: 120 train, 34 validation, 39 test. Включены правила, типы, exact-title priority и допуск карточек. Отдельно — **64 пары**: 20 коротких и 8 длинных перестановок, 20 синонимических пар, 4 отрицания, 4 изменения оформления, 8 изменений смысла.
- На отдельном корпусе из **50000 синтетических документов** выполнены 100 запросов и их перестановки. Все оценки конечные и неотрицательные, результаты перестановок совпали. Построение 6.06 с, p50 15.63 мс, p95 16.27 мс. Это только BM25 на одной машине, не нагрузочный тест API/embeddings.
- Сравнены **90** комбинаций k1/b/веса заголовка, затем **27** комбинаций весов метаданных/тела/dense. Выбор только по validation, после него показан test; неопределённость рассчитана парным bootstrap семейств.
- Ruff lint, выбранные security-правила, форматирование 70 Python-файлов, compileall, синтаксис JS и shell — без ошибок. Это не полная сертификация безопасности.
- Выполнен пробный цикл обучения **200** слабых синтетических запросов: 131 train / 24 validation / 45 test, 12 вариантов CatBoost. Рабочая модель не заменялась. Само обучение проверяет работоспособность pipeline, не подтверждает релевантность слабых меток.

Снимок: 1469 карточек, пользовательский поиск — 1118 после исключения терминов; 23820 векторных фрагментов. Каталог SHA-256: `904256290a10eeec3f1eaffec7636de032f294f53953a008839ded9f3263941f`. [Прогон до исправлений](../evaluation/audit_before/report.json), [итоговый прогон](../evaluation/audit_release/report.json). Хеши runtime-кода зафиксированы в отчётах; итоговый прогон соответствует текущему коду. Промежуточные дубликаты отчётов убраны.

## Качество итоговой выдачи

| Режим | Validation pooled NDCG@5 | Test pooled NDCG@5 | Test pooled MRR@5 | Test judged@5 |
|---|---:|---:|---:|---:|
| bm25 | 0.1574 | 0.1213 | 0.1481 | 0.0296 |
| hybrid | 0.4259 | 0.6416 | 0.7519 | 0.2030 |
| catboost | 0.4297 | 0.6033 | 0.7160 | 0.1837 |
| ensemble | 0.4767 | 0.6311 | 0.7383 | 0.2104 |

Это семейные средние. На запрос размечены всего четыре карточки, оценки составлены ассистентом; неизвестные **условно считаются нулями только в явно названных pooled-метриках**. Test уже наблюдался при разработке. Низкий judged@5 показывает неполноту разметки; таблица не является достоверной Precision/NDCG всего каталога. Разница hybrid и ensemble не доказывает статистического или продуктового превосходства. Улучшения общей релевантности по этим 193 запросам после исправлений не обнаружено: их метрики совпали с исходным прогоном.

Лексический режим на этом тесте часто возвращает пусто: действующая политика требует покрытия 0.85, которое редко достигается для естественных длинных запросов. Это проблема сочетания retrieval и gate; подбор k1/b сам по себе её не решит. Старые отчёты до политики допуска оценивали другие списки — их более высокие числа нельзя напрямую сравнивать с этой таблицей.

## Устойчивость

Таблица относится к ансамблю без LLM. «Совпадает» означает одинаковые ID **и порядок** top-5.

| Изменение запроса | До | После | Обе выдачи пустые после |
|---|---:|---:|---:|
| Короткие перестановки | 20/20 | 20/20 | 1 |
| Длинные перестановки | 3/8 | 3/8 | 0 |
| Синонимы/близкие формулировки | 2/20 | 8/20 | 0 |
| Эквивалентные противопоставления | 4/4 | 4/4 | 0 |
| Регистр, пробелы, ё/е, пунктуация | 3/4 | 4/4 | 0 |

Из 20 коротких пар одна пара пуста с обеих сторон; это не успешный поиск. Для синонимов обе стороны непусты в 17 из 20 пар, а полный порядок совпадает в 8. Средний Jaccard top-5 для синонимов ансамбля вырос с 0.205 до 0.470. Улучшение связано с четырьмя явными правилами HR-фраз; общей устойчивости к произвольным синонимам **нет**. Часть пар выражает близкие, но не строго тождественные намерения — нужна человеческая проверка.

Длинные перестановки остаются неустойчивыми: 3/8 полностью одинаковых порядков, хотя первый материал совпадает во всех восьми парах. Сортировать слова во всех длинных фразах нельзя: меняются субъект, объект и область отрицания. Для восьми контрольных изменений смысла совпадение не является целью. В одном случае ансамбль всё ещё выдал полностью одинаковый список для разных задач; это дефект чувствительности к намерению, а не плюс устойчивости.

На 24 старых no-answer пробах для hybrid/CatBoost/ensemble: все 12 предположительно отсутствующих тем дали пустой основной список, но один из 12 предположительно присутствующих тоже оказался пустым. Для BM25 — пять таких пропусков. Метки предварительные; это не доказательство отсутствия ответа во всём каталоге, а альтернативы здесь не оценивались.

## Подбор BM25

Первая сетка: `k1 ∈ {0.3,0.8,1.2,1.5,2,3}`, `b ∈ {0,0.25,0.5,0.75,1}`, `title ∈ {1,2,4}`. Затем общий вес topics/tags/industries, вес body и dense_weight перебраны по трём значениям. Остальные параметры фиксированы. Это последовательный поиск в ограниченной сетке, а не глобальная оптимизация всех весов и порогов.

Лучший validation-кандидат: **k1=0.8, b=0**, title=1, description=1, topics/tags/industries=1, body=0.75, lessons=0.75, dense_weight=1, RRF k=60. Эти значения относятся ко всей выбранной комбинации; нельзя приписывать весь эффект одному b.

| Hybrid | Validation pooled NDCG@5 | Test pooled NDCG@5 |
|---|---:|---:|
| Исходные параметры | 0.4259 | 0.6416 |
| Выбранная комбинация | 0.4757 | 0.6304 |

Test delta = -0.0113; 95% bootstrap CI по 9 семействам: [-0.0650; 0.0339]. Интервал включает ноль, точечная оценка отрицательна. Validation-интервал после выбора по той же выборке оптимистичен и не доказывает значимость. **Рабочие k1=1.5/b=0.75 сохранены.**

[Все комбинации и сравнения](../evaluation/bm25_calibration/report.json), [первичная сетка](../evaluation/bm25_calibration/bm25_trials.json), [вторичная сетка](../evaluation/bm25_calibration/fusion_trials.json), [экспериментальная конфигурация](../evaluation/bm25_calibration/selected_config.json). Подбор относится к hybrid, а не автоматически к CatBoost или ансамблю. Для их применения с другим BM25 нужны переобучение и перекалибровка; проверка совместимости теперь не позволяет менять признаки незаметно.

## Исправления кода и математики

1. BM25 использует обратные списки term→документы и фиксированный порядок суммирования; не перебирает все документы для каждого терма. Формула проверена независимым расчётом. Пустой/нулевой dense-канал и отключённый компонент ансамбля больше не добавляют произвольные кандидаты.
2. k1/b добавлены в `RankingConfig`, проходят диапазонную проверку и действительно передаются в полевые индексы. NaN/inf/логические значения и дробные размеры выдачи отклоняются. Конфигурация каталога проверяется один раз при загрузке.
3. Убрана зависимость движка от CLI: хеши, чтение bundle и загрузка encoder вынесены в `bundle.py`. Старые импорты CLI сохранены для совместимости скриптов.
4. Добавлены только ограниченные эквивалентные HR-фразы. Сохраняется оригинальный запрос; применённые правила видны в JSON. Конечная точка больше не становится частью последнего поискового слова; `.NET` сохраняется.
5. «Точное название» сравнивает последовательность нормализованных слов, а не множество: перестановка субъекта и объекта не выдаётся за буквальное название. Отдельный `ranking_override` объясняет приоритет выбора/точного заголовка.
6. `final_score` теперь доступен во всех режимах и отражает последнюю числовую стадию с применимыми правилами. Это не вероятность; разные режимы имеют разные шкалы. Поля BM25/cosine/RRF/CatBoost сохраняются отдельно.
7. Объяснения и рекламные поля формируются только для карточек, которые попадут в основной список/альтернативы, вместо всех допущенных кандидатов. Число возвращённых карточек не меняется из-за этой оптимизации.
8. Исправлен API default для сервера без embeddings и подключён реально работающий CLI-флаг `--no-llm`. Неиспользуемый `--install-small` теперь публикует модель и метаданные под блокировкой с проверкой неизменности каталога/векторов/конфига. Рабочие артефакты этим аудитом не заменялись.
9. Обучающий скрипт и подбор ансамбля теперь применяют тот же query plan, канонизацию embedding-запроса, допустимые типы и активные параметры BM25. Это исправление train/serve расхождения; старые численные отчёты остаются историческими. Внутренние списки обучения всё равно не заменяют end-to-end оценку gate.

## Архитектура и оставшиеся ограничения

Модульная структура достаточна для локального прототипа; отдельные сервисы и векторная БД здесь пока не нужны. Оркестратор `SearchEngine.search` остаётся большим и требует постепенного разделения. Полная атомарная публикация embedding-комплекта не реализована: `embed` обновляет несколько файлов внутри поколения, поэтому перед пересборкой нужно остановить сервер. Старые embedding metadata могут не иметь fingerprint; полного lock транзитивных зависимостей и проверки чистой установки нет. Docker в этом аудите не запускался.

Зависимые голоса ансамбля не дают трёх независимых свидетельств. RRF теряет величину разрыва скоров. Max pooling по фрагментам смещает шанс совпадения в пользу длинных текстов. Gate с лексическим предметом теряет часть настоящих синонимов. Пороги 0.85/0.62/0.48 не калиброваны на независимой разметке. Сложные отрицания, разные роли сторон, несколько целей и неподтверждённые ограничения нельзя считать решёнными. Эти ограничения требуют данных и отдельных экспериментов, а не декларации «все тесты прошли».

## Как воспроизвести

Из `05_code` с подготовленными локальными артефактами:

```bash
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v
.venv/bin/ruff check src tests scripts
.venv/bin/ruff check src --extend-select S
.venv/bin/ruff format --check src tests scripts
PYTHONPATH=src HF_HUB_OFFLINE=1 .venv/bin/python scripts/audit_ranking.py \
  --phase full --output evaluation/my_new_audit
PYTHONPATH=src .venv/bin/python scripts/audit_training_data.py \
  --output evaluation/my_training_data.json
PYTHONPATH=src .venv/bin/python scripts/audit_docs.py \
  --output evaluation/my_documentation_audit.json
```

Папка поискового отчёта должна быть новой. `baseline` отдельно запускает качество/устойчивость/масштаб, `calibrate` — подбор. LLM отключена; loopback нужен для HTTP-тестов. Автоматическое обучение/установка рабочих весов в этом аудите не выполняется.
