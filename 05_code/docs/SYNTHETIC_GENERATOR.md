# Локальный генератор синтетических запросов

## Зачем он нужен

Генератор создаёт воспроизводимые сценарии для проверки поиска и подсказок из доступных заголовков, описаний и тематических полей каталога. Он не вызывает LLM, не использует API и не расходует токены. Историю пользователей, события, покупки, доход, цены и оценки релевантности он не выдумывает. Никакие модели и веса после запуска автоматически не меняются.

Это прежде всего **набор проверочных запросов**, а не готовый золотой датасет: ссылка на исходную карточку показывает происхождение текста и не доказывает, что это лучший или единственный ответ. Для большинства строк это `label_status=weak_source_reference`, у открытых тем, противопоставлений и внепредметных запросов — `unjudged`. Поле `relevance` всегда `null`: другие карточки нельзя автоматически считать нерелевантными. Исследования также показывают, что среди автоматически подобранных отрицательных примеров встречаются действительно полезные материалы ([Hard Negatives, Hard Lessons, EMNLP 2025](https://aclanthology.org/2025.findings-emnlp.481/)).

## Из чего строятся запросы

- Полное название, короткий фрагмент, запрос с указанием формата и вариант с нейтральной рамкой.
- Фрагменты описаний, отличающиеся от названия по словам; у них слабая связь с карточкой и возможны обрывы текста.
- Одна перестановка соседних букв как проверка опечаток.
- Незавершённый префикс названия для **autocomplete**, отдельно от полного поиска.
- Открытые ситуации по теме, противопоставления двух тем и шесть намеренно внепредметных проверок. Для них ответ и его отсутствие не размечены.

Слова и темы взяты из выгрузки, поэтому генератор наследует её ошибки. Например, в каталоге встречается написание «Маркeтплейсы» с латинской `e`; оно может появиться и в синтетике. Простые эвристики отбрасывают часть неестественных окончаний и очень похожие темы в противопоставлении, но не гарантируют естественную речь или правильное понимание задачи.

Группы строятся по нормализованному названию; похожие названия дополнительно объединяются по ограниченной лексической близости. Каждая группа с фиксированным seed попадает целиком в train / validation / test. Точные повторы запросов удаляются глобально. 87 карточек из прежних оценочных наборов, совпадающие названия и совпадающие старые запросы исключены. Эта защита не находит все смысловые дубли; темы и весь каталог также известны при создании и индексации. Полученный `test` **не является независимым слепым тестом**. Не объединяйте без дополнительной проверки разные запуски с разными seed: одна группа может попасть в разные части.

## Проверенный запуск

Для текущего каталога и seed 42 создан набор `artifacts/synthetic/release_seed42/`:

|---|---:|
| Всего сценариев | 8 605 |
| Полный поиск / префиксы подсказок | 7 555 / 1 050 |
| Train / validation / test | 6 112 / 1 254 / 1 239 |
| Разных исходных карточек | 1 377 из 1 469 |
| Из них курсов | 21 из 26 |
| Не имеющих исходной карточки и разметки | 209 |
| Запросов с опечаткой | 1 283 |
| Ситуаций по теме / контрастов тем | 116 / 58 |

Курсы и некоторые другие карточки исключены потому, что уже встречались в прежних оценочных наборах; ещё пять карточек исключены из-за ограничений к названию. Это не представительное распределение пользователей: бо́льшая часть запросов образована непосредственно из текста карточки, и материалы разных видов покрыты неодинаково.

Два независимых запуска с одним seed дали одинаковый `queries.jsonl`, а также одинаковые файлы для ручной проверки. Независимый аудит не нашёл точных повторов, пересечения групп/исходных карточек между частями или совпадений с защищёнными примерами. Проверка похожих названий не нашла оставшихся пересечений по своей ограниченной эвристике; другие смысловые пересечения возможны. Manifest фиксирует seed и SHA-256 каталога, защищённых файлов, запросов, проверочной выборки и файлов генератора.

Для дополнительной проверки 90 запросов с известной **исходной карточкой** отобраны поровну по шести типам и прогнаны через текущий поиск без LLM. Исходная карточка оказалась в первой пятёрке в **90 из 90** случаев. Это не Precision@5, не измерение полезности и не «100% качества»: запросы получены из тех же текстов, которые лежат в индексе, а выборка специально сбалансирована по типам. Наоборот, этот результат показывает, что набор во многом слишком лёгкий для финальной оценки. Открытые и внепредметные запросы в данный тест не включались.

При выборочном просмотре примеров также обнаружены искусственные формулировки и обрезанные фразы описаний. Часть очевидных случаев исправлена правилами, но полная естественность не подтверждена. В `review.md` есть 120 выбранных примеров для вашей проверки; это незавершённая разметка, а не результат независимого эксперта.

## Файлы результата

- `queries.jsonl` — все запросы с типом, группой, split, источником и `relevance: null`.
- `review.md` — 120 примеров для просмотра и отметок с исходной карточкой, если она есть.
- `review.jsonl` — те же примеры в машинном формате с полями для ручной проверки.
- `manifest.json` — версии и контрольные хеши; `report.json` — распределение и исключения.
- `audit.json` — независимые структурные проверки и выборка для аудита.
- `smoke_search.json` — 90 отдельных результатов проверки нахождения исходной карточки.

`review.md` и `review.jsonl` предназначены для редактирования, но **не синхронизируются друг с другом и пока автоматически не импортируются в обучение**. Если изменить их, аудит покажет изменение контрольной суммы как информационное сообщение. `queries.jsonl` не следует редактировать вручную без создания новой версии набора.

## Как повторить

Откройте Terminal в `05_code`. Укажите **новую** папку вывода: существующая папка не перезаписывается.

```bash
PYTHONPATH=src .venv/bin/python scripts/generate_synthetic.py \
  --output artifacts/synthetic/my_run_seed42 --seed 42

PYTHONPATH=src .venv/bin/python scripts/audit_synthetic.py \
  artifacts/synthetic/my_run_seed42 \
  --output artifacts/synthetic/my_run_seed42/audit.json
```

Чтобы отдельно проверить воспроизводимость, создайте вторую новую папку с тем же seed и передайте её в `--compare`. Для проверки поисковой выдачи нужны готовые эмбеддинги, CatBoost и веса:

```bash
PYTHONPATH=src .venv/bin/python scripts/smoke_synthetic_search.py \
  artifacts/synthetic/my_run_seed42 \
  --output artifacts/synthetic/my_run_seed42/smoke_search.json --size 90
```

Файлы `artifacts/` хранятся локально и исключены из Git. Следующий шаг к настоящему gold: собрать отдельные пользовательские задачи, объединить кандидатов нескольких поисковых методов и разметить весь полученный пул людьми; после этого выделить действительно закрытый test и сравнивать ранжировщики на одинаковых данных.
