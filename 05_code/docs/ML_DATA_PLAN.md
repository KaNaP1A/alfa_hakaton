# Следующее обучение: цель, достоверные данные и синтетика

Дата: 12 ноября 2026. Вывод: ML здесь имеет смысл как обучаемая релевантность пары запрос–материал. CatBoostRanker уже реализован; основной недостаток — достоверные метки и проверка, а не отсутствие обучения как такового.

## Что предсказывать

| Задача | Строка обучения и target | Данные и оценка |
|---|---|---|
| Поисковое ранжирование — первый приоритет | запрос + материал + признаки → релевантность 0–3; группа — запрос/контекст | Независимая оценка кандидатов; family-macro NDCG@5, MRR@5, candidate recall |
| Достаточность ответа — отдельно | запрос + кандидатный пул → есть прямой ответ / только близкий / нет подтверждения | Глубокая проверка каталога; ложные ответы и пропуски по отдельности |
| Персональная рекомендация — позже | проверенная история до момента рекомендации + материал → полезный следующий шаг | Реальные взаимодействия и временные/пользовательские splits; отдельные cold-start срезы |
| Покупка или uplift — пока данных нет | показ + контекст + подтверждённый исход в фиксированном окне | Достоверные показы и оплаты; для причинного эффекта контролируемый эксперимент |

Не нужно назначать человеку одну категорию и учить классификатор «кофейня/налоги/маркетинг». Одна задача касается нескольких тем. Тип материала, отрасль, стадия бизнеса, субъект (клиент/работник), цель (запуск/погашение/взыскание), формат и ограничения полезны как признаки и **срезы оценки**. Они не заменяют target релевантности. Существующие пять категорий главной — эвристика интерфейса, не пять классов ML.

## Что подтверждено текущей базой

Пересчитано скриптом `scripts/audit_training_data.py`; агрегаты сохранены в [training_data_audit.json](../evaluation/training_data_audit.json). Пользовательские строки и ID не экспортировались.

- 10050 связей пользователь–курс, 7342 пользователя, 29 курсов; у 5780 пользователей только один distinct курс. История узкая и разреженная, почти не покрывает остальные типы каталога.
- 1266 связей отмечены завершёнными. Это потенциальный сигнал обучения после проверки семантики, не покупка и не поисковая релевантность.
- Только 22 `IsPaid=true`, заполненных `BuyingDate` — 0. Достоверную модель покупки на этих признаках построить нельзя.
- 8343 оценки, из них 7033 пятёрки; UserId заполнен только в 2325. Нельзя приписывать их произвольной карточке без проверки типа сущности; сильное смещение в положительную сторону.
- В 225 связях курса и 9624 связях урока `Completed < Created`. Нельзя использовать Created как гарантированный момент начала действия или текущий статус как исторический признак.
- Нет подтверждённого журнала запросов, показов и позиций. Отсутствующая связь пользователя с материалом не доказывает, что он видел и отверг материал.

В [старом крупном эксперименте](../evaluation/large_results/README.md) MRR около 0.996 получен на запросах из фрагментов индексируемых названий/описаний. Это обнаружение исходной карточки на лёгком наборе; оно не доказывает качество рекомендаций людям.

## Минимально полезный набор

Предлагаемый первый цикл: 300–500 самостоятельно сформулированных задач, 15–30 кандидатов на задачу (4500–15000 оценок). Это бюджет разметки, не обещание достаточного объёма. Дальше строить learning curve и расширять слабые срезы, а не заранее требовать миллионы строк.

Срезы: запуск бизнеса и общепит; финансы/налоги; найм/увольнение/мотивация; маркетинг/продажи/маркетплейсы; аренда/договоры/товарные знаки; технологии/данные; редкие подкасты и вебинары. В каждом нужны короткие и длинные задачи, несколько правильных ответов, неоднозначные и отсутствующие темы, ограничения и трудные противоположные смыслы.

Пул: объединить top-кандидатов BM25, dense, hybrid, текущего ranker и небольшую случайную допустимую выборку. Добавить трудные близкие примеры, но **проверить их**: другой документ тоже может быть полезным. Два оценщика независимо ставят 0–3 или unknown, не видя метод/позицию. Разногласия разрешаются отдельно. Готовая [инструкция и инструменты](ANNOTATION_GUIDE.md) уже есть; текущий пул не размечен.

## Как синтетика может помочь

Да, качественная синтетика может расширить словарь и разнообразие train. В InPars показана польза сгенерированных запросов для обучения retrieval на исследованных наборах; это основание проверить гипотезу здесь, а не обещание такого же эффекта. [InPars, первичная публикация](https://arxiv.org/abs/2202.05144).

1. Сначала выделить семейства train/validation/test. Генерировать обучающие перефразировки только для train; все варианты исходной задачи держать вместе. Дедуплицировать также близкие задачи и шаблоны. Если оценивается перенос на новые материалы, отдельно разделить материалы; обычный поиск по известному каталогу — другой режим проверки.
2. Генерировать от проверенных фактов каталога: обычная речь, описания проблемы без терминов карточки, допустимые синонимы, опечатки, разные уровни подробности и контексты отраслей. Сохранять source ID, evidence, generator/model/prompt version, seed и статус проверки.
3. Не придумывать содержание курса, цену, права, покупки и поведение пользователей. Связь с исходной карточкой считать слабой меткой, пока релевантность не проверена. Перефразировка должна сохранять цель и ограничения, а не только общую тему.
4. Различать близкие отрицательные и реально неизвестные примеры. Кандидат без оценки остаётся unknown. Данные самого теста и его оценки не передаются генератору/настройке.
5. Редкие и спорные случаи проверять людьми; выборочно контролировать остальные. Автоматические схемы/фильтры находят структурные ошибки, но не подтверждают полезность.
6. Сравнить на одном закрытом человеческом тесте четыре варианта: текущий hybrid; ML на человеческих оценках; ML на синтетике; ML на смеси. Пропорцию смеси выбирать по validation и learning curve. Показать confidence intervals по семействам, худшие срезы и время ответа.

Тысячи почти одинаковых фрагментов не равны тысячам независимых задач. Синтетика годится и для регрессии, и для дополнительного обучения; финальный gold должен иметь независимую человеческую проверку. Более крупная модель сама по себе не делает метки достоверными.

## Последовательность моделей

Сначала сильный BM25/hybrid и простой CatBoostRanker с согласованными train/serve признаками. Затем, если ошибки действительно связаны со смыслом, сравнить предобученный парный reranker и его адаптацию; для нового retriever отдельно измерить candidate recall. Обучать большую генеративную модель с нуля здесь пока не обосновано. Модель не отменяет проверки доступа и неопределённых ограничений.

Для будущих кликов сохранять показ, позицию, версию выдачи и подтверждённые исходы. Клики смещены позицией: прямое обучение «клик = релевантность» может воспроизвести старое ранжирование. Методы коррекции требуют собственных предпосылок и оценки propensity. [Joachims et al., Unbiased Learning-to-Rank with Biased Feedback](https://www.microsoft.com/en-us/research/publication/unbiased-learning-rank-biased-feedback/).

Решение о выпуске: преимущество на validation и новом закрытом test, отсутствие деградации критических срезов, приемлемая задержка, воспроизводимые артефакты. Рост покупок проверяется отдельно после интеграции реальных событий.
