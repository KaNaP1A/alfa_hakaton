# Многотипный эксперимент на историческом каталоге

## Статус

Это **не обучение на полном актуальном сайте**. Прямой сбор открытых данных сайта остановился на проверке HTTPS: `CERTIFICATE_VERIFY_FAILED`, self-signed certificate in chain. Браузер также не доверяет соединению. Не установлено, где именно возникает ошибка — на сайте или в сетевой среде. Сборщик не отключает проверку TLS и не обходит ограничения. Веб-поиск показывает отдельные индексированные страницы, но не является полной выгрузкой.

Чтобы продвинуть работу, использован уже имевшийся локальный снимок `artifacts/catalog`: 1476 карточек, включая 351 термин, который действующий пользовательский поиск намеренно исключает. В снимке 834 статьи, 247 документов, 26 курсов, 8 подкастов, 3 вебинара и 7 калькуляторов. Каталог не является актуальным набором оферт. Метки доступа снимка: `open` 861, `unknown` 605, `paid` 1, `subscription` 9. Они относятся только к снимку и не подтверждают сегодняшние права или цены; нельзя приравнивать стоимость курса и доступ по подписке.

По [индексированной странице сайта](https://kurs.alfabank.ru/courses/biznes-bez-trevog-zapusk-proekta-v-sfere-uslug/) навигация перечисляет больше курсов, подкастов и вебинаров, чем в снимке. Счётчики могут устареть и не являются сверкой полного каталога. Локальный набор не включает подтверждённые отдельно продаваемые уроки.

## Что подготовлено

[Сборщик](../scripts/collect_public_catalog.py) — начальная реализация для **публичных HTML-метаданных**: соблюдает `robots.txt`, ограничивает частоту, принимает только HTTPS и исходный хост, не скачивает материалы уроков, не сохраняет личные данные и не выдаёт отсутствие цены за бесплатный доступ. Реальную структуру сайта, пагинацию, JavaScript/API и покрытие проверить не удалось; `coverage_verified` всегда `false`. У него пока нет полноценного восстановления после обрыва. Даже после успешного сбора его отчёт нельзя считать доказательством полноты без сверки с каталогом платформы.

[Симулятор](../scripts/train_mixed_catalog_simulation.py) использует имеющиеся карточки и ранее построенные E5-векторы: для вымышленной задачи берётся карточка-опора, подбираются похожие и случайные кандидаты, а косинус между векторами используется как один из признаков. **Новых реальных пользовательских запросов не получено; E5 не дообучалась.** Близость между двумя карточками — не метка истинной релевантности запросу.

Все пользователи, бюджеты, цены, статусы оферты и события — **искусственные**. Режимы `free`, `paid`, `subscription` назначаются как контрфактические гипотезы, независимо от реального доступа карточки. Например, синтетическая «покупка после бесплатного материала» моделирует предположение о последующем действии, а не зарегистрированную покупку. Эти статусы нельзя показывать пользователю и нельзя обновлять ими каталог. При неизвестном бюджете модель получает отдельный признак отсутствия значения; непоказанное не маркируется как отказ.

Карточки с одинаковым нормализованным названием и типом отправляются в один split: 1032 train, 149 validation и 295 test. Уникальные карточки теста не используются для обучения, но смысловые дубли и темы могут пересекаться; разделение не по реальным людям. Всего создано 5000 train-сессий, 1000 validation и по 1500 test и stress-сессий. В train 50 000 пар, из них 22 574 помечены искусственно просмотренными. Каждый элемент снимка используется в качестве карточки-опоры в своём split; 295 тестовых и 149 validation-карточек не используются при обучении моделей.

Обучены две отдельные модели CatBoostClassifier — на синтетическое вовлечение и синтетическую покупку после показа. Это **не переобучение действующего CatBoostRanker**, не модель реальных продаж и не продакшен-система. Исходный BM25 + E5 + CatBoostRanker и HTTP API не менялись.

## Проверка

На отложенных по карточкам синтетических test-сессиях:

| Цель симулятора | ROC-AUC | LogLoss модели | LogLoss постоянного baseline |
|---|---:|---:|---:|
| Вовлечение | 0,656 | 0,627 | 0,677 |
| Покупка | 0,638 | 0,279 | 0,290 |

В stress-сценарии с большей ценовой чувствительностью AUC составила 0,696 и 0,649 соответственно. **Это способность воспроизводить придуманные правила, а не оценка реальных людей.** Метрики по редким типам ненадёжны: в test искусственно увидены только 24 подкаста и 24 вебинара; для задачи покупки искусственных положительных меток 3 и 1 соответственно. Эксперимент не проверяет коммерческое ранжирование на продажах, не измеряет удержание и не оценивает реальный рост выручки.

Проектные проверки: тесты симулятора разделяют карточки по названиям и типам, проверяют воспроизводимую генерацию, синтетические статусы и отсутствие отрицательных меток для непоказанного. Тесты сборщика проверяют границы домена, исключение страниц уроков/логина, `unknown` для цен и остановку при недоступном `robots.txt`. Синтетическая модель не подключена к выдаче.

## Повторный запуск

В `05_code`, с локальными зависимостями и совместимым индексом:

```bash
PYTHONPATH=src HF_HUB_OFFLINE=1 OPENBLAS_NUM_THREADS=2 .venv/bin/python \
  scripts/train_mixed_catalog_simulation.py --output artifacts/mixed_catalog_simulation_new
```

Создаются `synthetic_engaged.cbm`, `synthetic_purchased.cbm`, синтетические записи, отчёт и манифест с хешами входного каталога, векторов, кода и моделей. Папка должна быть новой. Артефакты и записи производны от закрытого исторического снимка, исключены из Git и требуют безопасной передачи.

После исправления доверенного соединения можно **исследовать** сбор публичных метаданных:

```bash
PYTHONPATH=src .venv/bin/python scripts/collect_public_catalog.py \
  --output artifacts/public_site_collect_new --max-pages 3000 --delay 1
```

Если сеть/сертификат/`robots.txt` недоступны, скрипт не начинает сбор. При необходимости команда сайта должна помочь с актуальным каталогом и безопасными условиями получения. Дальше нужно доработать сборщик на фактической структуре и проверить покрытие. Последовательность описана в [подробном плане](../../docs/ЕДИНЫЙ_ПЛАН_РАЗВИТИЯ_РЕКОМЕНДАЦИЙ.md).
