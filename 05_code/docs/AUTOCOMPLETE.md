# Подсказки, уроки и передача выбора в поиск

Реализованы все пять пунктов этапа: связи уроков; индекс подсказок; поиск неполного ввода и опечаток; связанные темы и выбор; тестовые сценарии. Это локальное ядро и API для интеграции, не изменение работающего сайта Альфы.

## Запуск

Команды из `05_code`, Python 3.11+ на macOS/Linux. Подсказки и BM25 работают без внешних библиотек, модели и ключей API.

```bash
PYTHONPATH=src python3 -m alfa_reco suggest "открыть коф"
PYTHONPATH=src python3 -m alfa_reco suggest "лояльность сотруд"
PYTHONPATH=src python3 -m alfa_reco suggest "договор арнеды"
PYTHONPATH=src python3 -m alfa_reco serve --port 8000
```

Для смыслового поиска добавьте `--hybrid` к serve. Модель загрузится один раз при старте. `/suggest` в обоих случаях не использует модель. `/search` по умолчанию выполняет BM25; для гибридного поиска передайте `mode=hybrid` серверу, запущенному с `--hybrid`.

```bash
curl --get 'http://127.0.0.1:8000/suggest' --data-urlencode 'q=открыть коф' --data 'limit=6'
curl --get 'http://127.0.0.1:8000/search' --data-urlencode 'q=Хочу открыть кофейню' --data 'mode=bm25'
```

Сервис слушает только 127.0.0.1. Это development API на стандартной библиотеке, не публичный production-сервер. Для сайта нужны интеграция команды фронтенда и развёртывание через production HTTP-сервис; не следует просто открывать этот порт наружу. CORS намеренно не включён: используйте same-origin backend/proxy. Пользовательские запросы не записываются в access log.

## Данные и политика уроков

`Lessons` связывается с курсами через `CourseLessonBindings`; `ParentGroupId` — ID урока-раздела, а не ID binding. Каждый предок проверяется в том же курсе. Группы разделов не превращаются в уроки.

Условия включения: курс уже допущен в каталог; lesson и binding явно не удалены; binding явно не закрыт; цепочка предков существует, не содержит циклов/дубликатов и также доступна. Неизвестные флаги, испорченные даты и неоднозначные связи исключаются с причиной в manifest.

Названия/описания уроков используются для открытых курсов; для платных/подписочных курсов — только при явном `IsTrial=true`. Это консервативная политика метаданных, не проверка права конкретного пользователя на просмотр. `direct_access_verified=false`; адрес урока не придумывается. Проверка реальных прав и авторизации — отдельный будущий этап.

`ClosedUntil` сравнивается только с явно заданным `build --as-of 2026-11-11T00:00:00Z`. Без `--as-of` все связи с заполненным `ClosedUntil` исключаются. Это сохраняет воспроизводимость вместо зависимости от текущего времени. После изменения даты/статусов каталог нужно пересобрать, а API перезапустить.

Уроки хранятся в `catalog[].lessons`. Их названия/описания дополняют поисковый текст родительского курса. Выдача содержит одну карточку курса, поле `matched_lessons` показывает до трёх лексически совпавших уроков. Это диагностическое совпадение, не сгенерированное обещание результата обучения. Отдельных страниц уроков и персонализации пока нет. Полные тела уроков/видео не индексируются. Для длинных программ embedding может обрезать текст по лимиту модели; BM25 использует весь подготовленный текст. Отдельные векторы уроков — последующее улучшение.

## Подготовка подсказок

`build` создаёт `suggestions.json` вместе с каталогом:

- Полные названия материалов и разрешённых уроков; существующие темы, теги, отрасли. Удалённые/непубличные значения справочников исключаются.
- Дополнительные короткие фразы из заголовков и описаний включаются, только если встречаются в двух разных материалах и хотя бы однажды в названии материала/урока. Это уменьшает число случайных фрагментов описаний.
- Для каждой записи сохраняются стабильный ID, исходный текст, тип, источники и ссылки на подтверждающие материалы. Сформулированных моделью фраз и большого ручного словаря синонимов нет.
- Порядок и контрольные суммы воспроизводимы. Индекс связан с хешем каталога; несовместимые и повреждённые файлы отклоняются.

Показанные формулировки могут быть названиями материалов или словами в исходной словоформе, например «кофеен». Это подбор подтверждённых фраз, а не генератор грамматически идеальных продолжений. Полноценную лемматизацию и оценку формулировок следует сравнить на разметке.

## Поиск во время ввода

После запуска индекс загружен в память: словарь, отсортированный список слов и обратные ссылки на записи. Последнее незавершённое слово ищется по префиксу, остальные — по форме и лёгкой нормализации окончаний. Для слов от четырёх символов при отсутствии обычного совпадения допускается одна вставка, удаление, замена или перестановка соседних букв; проверяются также нормализованные формы. Это ограниченная коррекция, не универсальное исправление текста.

Ввод ограничен 300 символами, выдача — 1–10 вариантами каждого вида. Пустая строка и один символ не запускают подбор. Служебные слова и небольшой набор глаголов цели не ограничивают кандидатов, но полный запрос участвует в ранжировании. Остальные значимые слова обязаны совпасть: нельзя молча отбросить «сотрудники» и предложить лояльность клиентов.

Порядок учитывает точное вхождение, число совпавших слов, источник, число подтверждающих материалов и длину. Встречаемость в каталоге не называется пользовательской популярностью: логов запросов для этого нет. Связанные темы подбираются по общим материалам, соответствующим всему существенному контексту, с уменьшением преимущества слишком широких тем. Семантической генерации связанных тем пока нет.

## Контракт API

`GET /suggest?q=...&limit=6`:

```json
{
  "query": "лояльность сотруд",
  "generation": "generation-...",
  "status": "matched",
  "typo_tolerant_match": false,
  "completions": [],
  "related_topics": [{
    "id": "stable-id",
    "label": "Управление командой",
    "kind": "topics",
    "support_count": 10,
    "context_support_count": 1,
    "evidence_entity_keys": ["article:..."],
    "selection": {"id": "stable-id", "generation": "generation-..."}
  }]
}
```

Числа и ID в схеме условные; фактические ответы — `artifacts/suggestion_examples.json`. `status` принимает `matched`, `no_match`, `insufficient_input`. `no_match` означает отсутствие совпадения в этом индексе, не доказанное отсутствие темы во всей базе.

При клике отправьте **исходный текст**, `selection_id` и `selection_generation` в `GET /search`, также можно передать `mode=bm25|hybrid`, `top=1..50`, `kind=course|article|document|...`. На CLI доступны `--selection-id` и `--selection-generation`.

Сервер разрешает ID только в своём индексе, не доверяет присланной клиентом подписи. Устаревшее поколение или неверный ID дают HTTP 400; запросите новые подсказки. Повторяющиеся/неизвестные параметры также дают 400, неизвестный endpoint — 404.

Выбор создаёт дополнительный канал кандидатов из связанных материалов. Он объединяется с исходными BM25/dense через RRF: k=60, веса каналов BM25=1, dense=1, selection=2. Это явная начальная конфигурация, ещё не обученные веса. Выбор влияет на ранжирование, но не отсекает остальные результаты. Фильтр типа материала сохраняется. Ответ возвращает исходный `query`, принятую `selection`, `selection_match` и оценки каналов.

`GET /health` возвращает поколение и доступность hybrid. Сервер использует один snapshot до перезапуска; обновление каталога не меняет индекс посреди запроса.

## Подключение поля ввода на фронтенде

1. После изменения текста сбрасывать выбранную подсказку, ставить debounce около 150 мс. При composition/IME дождаться `compositionend`.
2. Отменять предыдущий fetch через AbortController; дополнительно проверять порядковый номер запроса перед отрисовкой — отмена не гарантирует, что старый ответ не успел прийти.
3. Показывать отдельно продолжения/материалы и связанные темы. Не заменять запрос без клика. Использовать `textContent`, не `innerHTML` для названий.
4. По клику сохранять ID + generation и вызывать `/search` с исходным текстом. Enter без выбора ищет исходный запрос. Escape закрывает подсказки. Добавить управление стрелками и доступные подписи элементов.
5. Ошибка подсказок не блокирует обычный поиск. `no_match` не заменять случайными категориями; пустой ввод просто скрывает список. При HTTP 400 из-за старого поколения обновить подсказки, не подставлять другой ID.

Само поле сайта и авторизация в этом этапе не менялись: здесь готова серверная часть и контракт интеграции.

## Проверки и навигация

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
PYTHONPATH=src python3 scripts/check_scenarios.py
PYTHONPATH=src python3 scripts/run_examples.py
python3 -m pip install -r requirements-dev.txt
ruff check src tests scripts
ruff format --check src tests scripts
```

HTTP-тесты открывают временный loopback-порт. `check_scenarios.py` проверяет конкретные smoke-сценарии и сохраняет время 300 тёплых вызовов. Это не NDCG, не оценка конверсии и не нагрузочный тест.

Модули: `lessons.py` — доступ и связи; `suggestions.py` — индекс/подсказки; `search.py` — единый движок/выбор; `server.py` — API; `text.py` — нормализация; `storage.py` — блокировка писателей; `cli.py` — импорт и команды. Одновременные build/embed запрещены файловой блокировкой, снимающейся при завершении процесса.
