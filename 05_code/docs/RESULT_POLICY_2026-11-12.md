# Исправления выдачи: уточнение, полезные материалы, тексты карточек

## Выбранный шаг передаётся отдельно

Раньше выбор «Как открыть ИП» добавлялся прямо в строку «открыть столовую». Семантический поиск оценивал склеенную фразу, а глобальный порог снова выдавал предупреждение. Даже точное название статьи могло не пройти прежний порог cosine.

Теперь исходная задача остаётся в `q`. Уточняющий вопрос содержит варианты с `label`, `kind` и подписанным `token`. UI показывает выбор отдельной плашкой и отправляет `clarification_token`. Сервер проверяет подпись, поколение каталога и исходный запрос. После изменения запроса или перезапуска сервера старый токен не подходит. Произвольный текст передаётся отдельным полем `clarification_text` длиной до 100 символов. Выбор подсказки и уточнение взаимно исключаются.

Для варианта конкретного материала поиск сосредотачивается на выбранном заголовке, выбранная карточка ставится первой. Ответ содержит исходный `query` и отдельный `focus`. UI сообщает «Вы выбрали: Как открыть ИП» и показывает материалы по этому шагу: он не утверждает, что статья о регистрации ИП покрывает все вопросы открытия столовой. Исходные неподтверждённые ограничения цены, опыта и отрицаний продолжают влиять на предупреждение. Уточнение можно снять или пропустить.

## Пользовательская выдача без словаря и заполнителей

`glossary` исключён из поиска, альтернатив, подсказок и рекомендаций главной. Данные словаря остаются в исходном каталоге и индексах для воспроизводимости предыдущих экспериментов. Материалы с другим типом не добавляются для заполнения выбранного числа позиций: `top` означает максимум.

Сначала ансамбль ранжирует кандидатов, затем отдельная политика проверяет каждую карточку. Сырые RRF/CatBoost не являются абсолютным сигналом релевантности. Точное название и явно выбранная карточка допускаются без требования к cosine. Для остальных нужны:

- покрытие не менее 0,85 содержательных слов запроса в заголовке/описании, включая предмет запроса; либо
- cosine карточки не менее 0,62 и совпадение предмета в заголовке/описании; либо
- высокое покрытие в программе уроков с подтверждающим смысловым сигналом.

Общие действия вроде «открыть» сами по себе не создают совпадение предмета: запрос «открыть столовую» не получает статьи про любой объект, который можно открыть. Явные конфликты поддерживаемых правил отрицаний и намерений не допускаются в основной список. Материалы без достаточных оснований, но с cosine не ниже 0,48, могут появиться в отдельном сворачиваемом блоке «Посмотреть близкие темы» — до трёх карточек. Ещё более слабые кандидаты не показываются. Порог 0,48 — инженерная граница для альтернатив, 0,85 — требование почти полного покрытия, а не оптимальные значения из независимой разметки. Значения требуют дальнейшей оценки на внешней разметке; простые совпадения всё ещё могут ошибаться по смыслу. Новая политика меняет выдачу и не подтверждает старые показатели качества.

Вопросы о следующих шагах формируются из короткого списка кандидатов до отсечения: это позволяет предложить регистрацию бизнеса, когда специального материала о столовой нет. Такие варианты не объявляются ответом на всю исходную задачу.

## Тексты для перехода к материалам

Шаблон «Для задачи ... может пригодиться ...» удалён. Карточка получает отдельное поле `promotion`, которое не повторяет пользовательский запрос и не показывает позиции методов. Для 52 материалов, включая все 26 курсов, подготовлены короткие редакционные тексты о действиях и пользе на основе реальных названий и описаний. Например:

> Превратите идею бизнеса в конкретный план регистрации: разберитесь с ОКВЭД и налоговым режимом, подготовкой и подписанием документов онлайн.

Редакционный текст связан с хешем исходных названия и описания. После их изменения автоматически применяется общий призыв по типу/названию; старый текст не выдаётся за описание нового содержания. Для остальных карточек используются общие формулировки и приглашение открыть материал. Это пока не уникальная рекламная редактура всего каталога. LLM не придумывает результат обучения, цену, скидку или гарантированный доход. Полное исходное описание доступно через «О материале».

Файл текстов `src/alfa_reco/promotion_copy.json` включён в пакет Python через `pyproject.toml`. Ссылки по-прежнему появляются только при наличии разрешённого полного URL; недостающие адреса не придумываются.

## Проверки

- `tests/test_result_policy.py`: задача со столовой, отдельный фокус, изменение запроса, подмена/перезапуск токена, исключение glossary, короткая выдача, точное название при слабой семантике, сохранение исходных ограничений, слабый кандидат, обновление исходника рекламного текста.
- `tests/test_api.py`: HTTP-передача уточнения и сохранение оригинального запроса.
- `scripts/check_result_policy.py`: реальные артефакты каталога, десять контрольных запросов, выбор «Как открыть ИП», две перестановки и отсутствие glossary. Отчёт: `evaluation/result_policy_2026_11_12.json`.

Повторить из `05_code`:

```bash
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests
PYTHONPATH=src .venv/bin/python scripts/check_result_policy.py
```

Это регрессионные проверки разработчика. Они не заменяют независимую разметку полезности каждой карточки и не доказывают отсутствие ошибок на остальных запросах.
