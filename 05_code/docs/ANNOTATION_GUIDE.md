# Независимая разметка выдачи

Подготовлен пул `artifacts/annotation_pool/complex_v3`: 75 задач, 25 семейств, 664 пары запрос–материал. Для каждой задачи объединены top-5 BM25, гибридного поиска и текущего ансамбля; дубли удалены, карточки перемешаны. В `review.md` порядок алгоритмов не показан. `pool.jsonl` содержит названия и описания; `rankings.jsonl` хранит исходные места отдельно. Запросы составлены ассистентом; разметка пока не выполнена и оценки отсутствуют. Это заготовка независимой оценки, а не готовый gold и не слепой test: примеры уже видны в проекте.

Пул покрывает только кандидатов нескольких систем и не доказывает отсутствие материала во всём каталоге. Группы семейств разделены: 54 запроса train, 6 validation, 15 test. Для полноценного закрытого теста нужна новая выборка, которую разработчики не просматривали и не использовали для настройки. Два оценщика должны работать независимо, не смотреть позиции из `rankings.jsonl` и сопоставлять каждую карточку с исходной задачей, а не только с совпавшим словом.

## Шкала

- `3` — напрямую помогает решить сформулированную задачу.
- `2` — частично полезен, но не покрывает основной вопрос или нужен важный контекст.
- `1` — общая связь с темой, существенный вопрос не решается.
- `0` — не относится или противоречит запросу.
- `null` — оценить нельзя. Не заменяйте его нулём.

В поле `reviewer_a`/`reviewer_b` допускается только `null` либо целое число 0–3. Если оценки двух людей различаются, нужна третья согласованная оценка в `adjudicated`. До её появления программа считает пару неоценённой. При сомнении лучше оставить `null`. Достоверность цены, уровня и прав доступа нельзя угадывать по неуказанным данным.

## Как работать

Можно открыть `Открыть лабораторию.command`, раздел «Разметка», заполнить свой столбец и экспортировать JSONL. Экспорт содержит все 814 пар, включая пустые; другой столбец и adjudicated не заполняются. Люди работают в отдельных профилях браузера и не смотрят чужие оценки. Автоподсказки скрыты; их раскрытие сохраняется даже после снятия галочки. Такие строки строгие merge/evaluation не принимают как слепую человеческую оценку. Описания в разделе разметки доступны целиком.

Создайте две копии исходного пустого `judgments.jsonl` и передайте каждому оценщику свою копию; каждый заполняет только свой столбец. `review.md` — удобный для чтения список, его галочки автоматически не импортируются в JSONL; для расчёта нужно заполнить JSONL. Оба файла сохраняются локально.

```bash
cd /path/to/Alfa-hak/05_code
cp artifacts/annotation_pool/complex_v3/judgments.jsonl artifacts/annotation_pool/complex_v3/reviewer_a.jsonl
cp artifacts/annotation_pool/complex_v3/judgments.jsonl artifacts/annotation_pool/complex_v3/reviewer_b.jsonl
```

Когда оба человека закончат и вернут файлы:

```bash
PYTHONPATH=src .venv/bin/python scripts/merge_reviews.py \
  artifacts/annotation_pool/complex_v3/reviewer_a.jsonl \
  artifacts/annotation_pool/complex_v3/reviewer_b.jsonl \
  --output artifacts/annotation_pool/complex_v3/judgments_merged.jsonl

PYTHONPATH=src .venv/bin/python scripts/evaluate_annotation_pool.py \
  artifacts/annotation_pool/complex_v3 \
  --judgments artifacts/annotation_pool/complex_v3/judgments_merged.jsonl \
  --output artifacts/annotation_pool/complex_v3/reviewed_metrics.json
```

Программа проверяет соответствие пар и контрольные суммы исходного пула и ранжирования. В метрики попадают только запросы с **полностью размеченным пулом**; остальные отдельно считаются ожидающими. P@5, MRR@5 и NDCG@5 рассчитываются по известному пулу и усредняются по семействам; NDCG не учитывает релевантные материалы вне пула. Неразмеченные и спорные материалы не превращаются в нули. На пустых оценках будет честное `completed_queries: 0` и метрик не будет. Отмечайте также случаи, где в пуле нет хорошего ответа: это не обязательно означает, что ответа нет во всей выгрузке.
