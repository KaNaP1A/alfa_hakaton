# Локальное обучение релевантности — 12 ноября 2026

> Подробное описание данных и новый синтетический подбор: [ML и отдельный holdout](ML_AND_SYNTHETIC_HOLDOUT_2026-11-12.md). Выбранный режим использует слабые пары; их общий вес масштабирован по сумме весов ассистентских train-пар. Исходный манифест это различие не пояснял, код будущих манифестов исправлен.

> Последующая проверка: [1000 сценариев, 120 длинных стресс-проб и полный автоматический пул](CHALLENGE_1000_2026-11-12.md). В автоматическом test relevance хуже исторического hybrid; человеческого подтверждения преимущества ML нет. Числа ниже относятся к первому, предварительному циклу.

Выполнено на Mac в проектном `.venv`: морфология русского языка, отдельный индекс E5 и обучение CatBoostRanker. Обучение — CPU, два потока; генерация дополнительных запросов — локальная Gemma через loopback. Облачная LLM не вызывалась. Из интернета скачаны только публичные веса encoder, затем обучение шло с `HF_HUB_OFFLINE=1`.

Новый профиль называется `relevance`; его можно запустить отдельным демо. Прежние BM25/hybrid/ансамбль доступны для сравнения. Модель и индекс опубликованы атомарным отдельным bundle, без замены исходных MiniLM/CatBoost-артефактов.

## Запустить результат

Дважды нажмите **[Запустить ML демо.command](../Запустить%20ML%20демо.command)** в Finder. Или из `05_code`:

```bash
PYTHONPATH=src .venv/bin/python -m alfa_reco serve --relevance --no-llm --open-browser --port 0
PYTHONPATH=src .venv/bin/python -m alfa_reco search "как выбрать франшизу кофейни" --mode relevance
```

Сервер с `--relevance` выбирает новый режим в API и браузере. Encoder E5 загружается локально, старый encoder для этого запуска не нужен. Исходный запрос сохраняется, выбор материала/темы и фильтр типа продолжают работать. Реальный HTTP-прогон проверил обычный и длинный запросы, а также отказ на квантовой механике.

## Как улучшена устойчивость

1. `pymorphy3` приводит словоформы к леммам: «работниками» и «работник» получают общую основу. Это отдельный индекс; новые признаки не подставляются старому CatBoost.
2. Для поисковых формулировок без защищённых отношений приводятся к одному виду отдельные связки действия и объекта; порядок независимых частей не меняет представление запроса. «Открыть магазин и найти покупателей» можно переставить по частям.
3. Конечные глаголы, отрицания, направленные предлоги и сложные конструкции сохраняют порядок. «Банк кредитует магазин» отличается от «магазин кредитует банк», а продажа магазина и покупка оборудования не схлопываются с обратными действиями. Это консервативная эвристика, не полноценный синтаксический анализ.
4. [multilingual-e5-small](https://huggingface.co/intfloat/multilingual-e5-small) используется как обученный поисковый encoder с требуемыми префиксами `query:`/`passage:`. Сам encoder **не дообучался**; в этой работе обучались деревья ранжирования поверх его признаков.

| Набор | Прежний ансамбль: полный одинаковый порядок | Новый профиль |
|---|---:|---:|
| Короткие перестановки | 20/20 | 20/20 |
| Длинные перестановки | 3/8 | 8/8 |
| Синонимы / близкие формулировки | 8/20 | 8/20 |
| Эквивалентные противопоставления | 4/4 | 4/4 |
| Оформление запроса | 4/4 | 4/4 |

У коротких пар одна выдача пуста с обеих сторон. Все восемь длинных пар непусты. Для синонимов полностью одинаковый порядок пока **8/20**; средний Jaccard вырос с 0.470 до 0.501, обе стороны непусты в 19 парах вместо 17. Не исправлен пример «снизить текучесть кадров» / «уменьшить текучесть сотрудников»: во втором случае основной список пуст. Это реальный оставшийся дефект, а не повод объявлять синонимы решёнными.

Для восьми изменений смысла новый профиль ни разу не вернул полностью одинаковый порядок; состав в одной паре всё ещё совпадает. Проверенные примеры не гарантируют правильный разбор любых ролей и отрицаний. Известные 64 пары использовались как регрессия после выбора модели/порогов, а не как метрика выбора гиперпараметров; они уже были видны при разработке правил и не являются слепым языковым тестом.

## Обучение пары «запрос–материал»

34 признака: BM25 семи нормализованных полей, E5-сходство карточки/названия/тем/уроков, покрытие предметных слов и редких терминов, пересечения тем/тегов/отраслей, тип материала и размеры метаданных. Категории участвуют в признаках и срезах, а не являются единственным классом пользователя. UUID и пользовательские записи не используются как признаки.

Сравнены **24 модели**: предварительные оценки ассистента, слабая синтетика, две смеси; глубины 3/5/6 и L2 3/10. Для каждой — 400 деревьев, PairLogit, learning rate 0.04, seed 42, CPU 2 потока. Ранжирование обучается предпочтениям внутри группы запроса; порядок оптимизируется по validation family-macro pooled NDCG@5 через настоящий API поиска, включая допуск карточек. Формат пар и их весов соответствует [CatBoost ranking](https://catboost.ai/docs/en/concepts/loss-functions-ranking).

Подготовлено 120 предварительно размеченных запросов и 800 слабых обучающих запросов, всего 6080 строк запрос–кандидат. Для известных оценок — 595 пар предпочтения, для синтетики — 4800 слабых source-over-sampled-item предпочтений. Среди 800 запросов: 192 локально сгенерированных, 204 фрагмента названия, 227 опечаток и 177 проблемных фрагментов описания. Генератор создал 193 допустимые по первичным фильтрам строки, одна не попала в итог после дедупликации.

Материалы всех прежних оценочных наборов, включая validation/test, исключены из источников синтетики и её сравниваемых кандидатов. Сначала выбиралась обучающая группа исходного материала, затем создавались варианты запроса. Это защита по ID/названиям, а не доказательство отсутствия всех смысловых пересечений. Семейства основного набора не пересекают train/validation/test.

У неизвестного кандидата оценка остаётся `null`. Синтетика задаёт **слабое относительное предпочтение** исходной карточки; она не доказывает нерелевантность других карточек. Для PairLogit передаются только явные пары с весами; техническая числовая заглушка target не создаёт дополнительных автоматически отрицательных примеров. В смеси общий вес синтетических предпочтений нормируется относительно предварительных оценок, чтобы количество копий не подавляло остальные данные.

На validation выбрана `synthetic_only_d6_l210`: отдельные пары — **слабые синтетические предпочтения**, 800 запросов / 5600 строк / 4800 пар, глубина 6, L2=10. Их общий вес масштабирован по ассистентским train-парам на коэффициент 0,83; сами ассистентские пары в выбранный pool не вошли. Утверждать, что победившая модель обучена на независимой человеческой релевантности, нельзя. Разница лучших режимов на восьми validation-семействах мала и не доказывает универсального преимущества синтетики.

## NDCG@5 и вклад компонентов

| Система | Validation pooled NDCG@5 | Test pooled NDCG@5 |
|---|---:|---:|
| Прежний hybrid | 0.4259 | 0.6416 |
| Прежний ансамбль | 0.4767 | 0.6311 |
| E5, канонизация, без нового ranker | 0.6628 | 0.7496 |
| Обученный профиль relevance | 0.6823 | 0.7487 |
| E5 по исходной фразе, без ranker — дополнительный разбор | 0.6318 | 0.7766 |

У нового профиля test MRR@5 = 0.8926; judged@5 = 0.2326. Средняя доля известных релевантных в пуле до ранжирования — 0.9487 по запросам. Ранжировщик не может вернуть документ, потерянный на этой стадии; нужен отдельный контроль recall. В метках всего набора также есть 15 положительных оценок терминов, исключённых пользовательской политикой; это требует согласования будущей разметки с допустимыми типами.

Разница test против старого hybrid: +0.1070, условный bootstrap CI по девяти семействам [0.0327; 0.1819]. **Это не подтверждённый прирост реального качества:** запросы и четыре оценки на запрос составлены ассистентом, test уже наблюдался, большая часть top-5 не размечена. Bootstrap не исправляет эти смещения.

Отдельное сравнение показывает: **основной прирост дал весь новый поисковый профиль — E5, морфология, пул и допуск. Сам CatBoost не доказал дополнительного выигрыша на test:** 0.7487 против 0.7496 без ranker при той же канонизации. На validation он выше: 0.6823 против 0.6628. Поэтому модель выбрана по validation, но нет оснований говорить, что обучение уже лучше готового encoder для реальных людей.

Дополнительный исходный E5 без канонизации дал 0.7766 на ранее просмотренном test, но только 0.6318 на validation. По test вариант не переключался. Этот результат показывает компромисс между устойчивостью представления и порядком; он не является новым победителем на закрытом тесте.

Важности признаков сохранены отдельно. E5 карточки даёт около 51% PredictionValuesChange; далее идут BM25 названия, покрытие предмета и редких слов. Это описание конкретных деревьев, не причинное объяснение полезности. Срезы по типам, длине запроса и темам положительных меток доступны в дополнительном отчёте; темы пересекаются, редкие срезы малы.

## Отсечение и отсутствие ответа

Для E5 нельзя переиспользовать порог 0.62 от MiniLM: шкала другая. На validation и старых 32 калибровочных пробах сравнены 18 политик, с ограничением ложной основной выдачи на предполагаемо отсутствующих темах. Выбрано: обычный semantic cosine от **0.84** с предметным совпадением, semantic-only от **0.92**, лексическое покрытие от **0.85**.

На прежних 24 отложенных пробах: 12/12 предполагаемо отсутствующих тем без основной выдачи и 12/12 предполагаемо присутствующих — с основной выдачей. Это метки разработчика, не глубокая независимая проверка каталога; полезность каждой возвращённой карточки не подтверждена. Пороги относятся только к этому encoder/профилю.

## Достоверность данных и следующий цикл

Все три прежних человеческих пула пусты. Подготовлен расширенный [review.md](../artifacts/annotation_pool/relevance_v1/review.md): **75 задач, 814 карточек**, порядок перемешан, оценки `null`. Старые baseline-списки сохраняют дату исходного снимка и помечены историческими; добавлен top-5 замороженного нового профиля. Этот пул ещё не слепой test и не human gold. Два независимых оценщика должны работать без `rankings.jsonl`, затем разрешить разногласия. [Инструкция](ANNOTATION_GUIDE.md).

Автоматическая проверка пула даёт `completed_queries=0` и пустые метрики: [evaluation_unjudged.json](../artifacts/annotation_pool/relevance_v1/evaluation_unjudged.json). Оценки не придуманы для завершения отчёта.

Дополнительный аудит локальной генерации нашёл **три** запроса с отрицанием или неподтверждёнными ограничениями; выборочное чтение также обнаружило расширение контекста. Следовательно, синтетика здесь **не имеет подтверждённого высокого качества**. Её записи остаются слабыми предпочтениями, а не достоверными оценками. Перед следующим циклом нужны отсев таких случаев и независимая оценка соответствия источнику. Генератор 1B и семантический фильтр сами по себе не подтверждают факты.

Для следующего улучшения синонимов нужен корпус действительно эквивалентных запросов, сохраняющих действие, объект и ограничения. После разметки можно сравнить контрастивную адаптацию encoder или парный reranker; простой набор новых замен не гарантирует обобщения. Для NDCG полезнее расширить и согласовать разметку, оценить потери кандидатов и проверить обучаемый ranker на свежем закрытом наборе, чем подбирать новые коэффициенты по уже просмотренному test. Текущая работа реализовала и запустила этот цикл на доступных слабых данных, но не заменила человеческую проверку.

140 автоматических тестов прошли. Ruff lint, выбранные security-правила, форматирование 78 Python-файлов, compileall, синтаксис JavaScript и shell — без ошибок. Для повторения на этом Mac дважды нажмите **[Обучить ML локально.command](../Обучить%20ML%20локально.command)**. Запуск создаёт новую папку, сохраняет старые отчёты и не меняет режим обычного демо. При наличии локальной Gemma генерируются новые train-запросы; без неё остаются исходные слабые варианты. Сгенерированный текст нужно хранить: повторная генерация не обязана быть побитово одинаковой.

Для нового окружения сначала установите `requirements-relevance.txt`. Затем из `05_code`:

```bash
.venv/bin/python -m pip install -r requirements-relevance.txt
PYTHONPATH=src .venv/bin/python scripts/download_relevance_encoder.py
PYTHONPATH=src .venv/bin/python scripts/run_relevance_pipeline.py --generate --install
```

Для воспроизведения текущего набора используйте сохранённые запросы и новую папку:

```bash
PYTHONPATH=src HF_HUB_OFFLINE=1 .venv/bin/python scripts/train_relevance.py \
  --output artifacts/relevance_runs/my_new_training \
  --index artifacts/relevance_v1/index \
  --local-queries artifacts/relevance_v1/local_queries/queries.jsonl \
  --synthetic-limit 800 --install
```

`--install` публикует отдельный экспериментальный bundle. Чтение идёт из фиксированного поколения; hashes каталога/нормализации/модели проверяются. После изменения кода представления нужен новый индекс и обучение, после установки — перезапуск ML-демо. Веса encoder закреплены revision `614241f622f53c4eeff9890bdc4f31cfecc418b3`.
