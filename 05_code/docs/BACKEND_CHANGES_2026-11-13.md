# Изменения для бэкенда — 13 ноября 2026

Рабочий поиск — `relevance`: BM25 и E5 участвуют в подборе кандидатов, CatBoost их ранжирует. Отдельный `mode=bm25` убран. Если клиент его передаёт, `/search` возвращает HTTP 400; используйте `mode=relevance` или опустите `mode`. Запуск без отдельного режима BM25 требует совместимого комплекта relevance. Скоры модели не являются вероятностями и не заменяют порядок результатов.

Для получения результатов используйте `/search`, `/recommend` и `/development-plan`, а для метаданных — подготовленный снимок `materials.jsonl`. Форматы, ограничения и примеры: [передача алгоритма бэкенду](BACKEND_HANDOFF.md). `entity_key` и `generation` связывают рекомендации с карточками и версией каталога; не смешивайте разные поколения.

Экспорт метаданных создаётся командой:

```sh
PYTHONPATH=src .venv/bin/python scripts/export_catalog_metadata.py \
  --catalog artifacts/catalog --output artifacts/backend_metadata_NEW
```

Он содержит заголовки, описания, темы, теги, отрасли, аудиторию при наличии, идентификаторы и происхождение полей, а также манифест с контрольными суммами. Новая папка должна отсутствовать до запуска. Для экспорта нужен локальный каталог с соответствующим `source.sqlite`: скрипт проверяет источник и не требует передавать его бэкенду.

Модель, каталог, метаданные и исходная база в репозиторий не входят. Комплект модели и каталог, а также отдельный снимок метаданных необходимо получить у владельца проекта защищённым способом. Метаданные не заменяют модель и не доказывают актуальную публикацию, цену, ссылку или право конкретного пользователя. Эти проверки остаются за бэкендом.

По исходному снимку проверены 1125 карточек, допущенных к поиску; у пяти нет описаний, у 482 нет публичной темы, у 64 нет тегов, у 931 пусто поле `industries`. В заполненном поле смешаны отрасли и другие метки: отраслевой или рыночный признак есть у 169 карточек. Пустые значения не заполняются предположениями. Данные непубличных тем в экспорт не добавляются. Каталог может измениться: не используйте эти количества как постоянную характеристику сервиса.
