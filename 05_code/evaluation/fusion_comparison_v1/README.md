# Сравнение сигналов ранжирования: сетка 0,25

Продолжение с сеткой 0,1 и дополнительной проверкой пересечений: [отчёт v2](../fusion_comparison_v2/README.md).

[Полные результаты 35 вариантов](report.json) получены локально на одном и том же пуле кандидатов, а затем на синтетическом dev. Рассмотрены все 15 непустых сочетаний BM25, MiniLM, E5 и обученного CatBoost. Веса неотрицательны, сумма равна 1, шаг сетки 0,25: это 35 точек, не все возможные вещественные веса. Каждый сигнал нормирован min-max внутри пула запроса. Оценивается сортировка уже заданных кандидатов, без реального поиска кандидатов и порогов выдачи. Это экспериментальная формула, не текущий `final_score` сайта.

У реального пула 75 запросов и 814 автоматически оценённых пар; термины исключены для всех методов одинаково. Разметка сделана локальными моделями, человек её не подтвердил. Validation содержит только 6 запросов из 2 семейств; test — 15 запросов из 5 семейств и ранее просматривался. Эти запросы использовались в предыдущих экспериментах, а validation — при выборе исходного профиля. Тест не является новым независимым holdout.

Последняя строка выбрана по validation NDCG@5, с фиксированным правилом разрешения ничьих, до расчёта синтетического dev. Разница с E5 на validation всего 0,0019, выбор по шести автоматически оценённым запросам неустойчив. На просмотренном test эта смесь не лучшая. CatBoost сам использует признаки BM25 и E5; его отдельный столбец не означает независимость компонентов. Текущий профиль не переключался на подобранные веса.

Синтетическая часть: 320 задач dev, 280 вымышленных карточек, полные шаблонные оценки. Для MiniLM в искусственном каталоге использован вектор названия и описания; реальный индекс использует отдельные единицы текста. Вложенные в карточки формулировки задачи и синонимов делают эти проверки лёгкими. Синтетический test, который уже был раскрыт, повторно не использовался.

На том же пуле набор кандидатов и идеальный список отличаются от прежнего отчёта 0,381/0,572, где оценивались готовые выдачи с порогами. Числа из двух методик напрямую сравнивать нельзя. Для выбора производственного алгоритма нужны новые независимые запросы, человеческая полная разметка, проверка полноты извлечения и полная оценка действующей выдачи с порогами.

## Проверка пересечений

После приведения регистра, «ё» и пунктуации к общему виду среди 172 текстов раскрытого синтетического test не нашлось точных совпадений с 800 слабыми запросами обучения или 120 ассистентскими train-запросами прежнего набора. Это проверка только точных текстов: она не исключает смысловых дублей, общей тематики, содержимого предобучения E5 или других утечек. При построении самого искусственного теста его цель и синоним явно вписывались в тестовый документ: это упрощение искусственной задачи и делает высокую оценку непоказательной для реального каталога; само по себе оно не доказывает утечку test в обучение. Прежнее название «закрытый тест» относится к разделению семейств и одноразовому прогону, а не к доказательству независимости реального качества.

Текущий скрипт теперь создаёт сетку 0,1 в папке v2. Запуск: из `05_code` выполнить `PYTHONPATH=src HF_HUB_OFFLINE=1 OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 .venv/bin/python scripts/compare_score_fusions.py`. Он не устанавливает результаты в поисковый профиль. Нужны локальные индексы, модели и автоматические оценки.
