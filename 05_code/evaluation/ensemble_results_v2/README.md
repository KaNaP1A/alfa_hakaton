# Объединение трёх методов: воспроизводимый эксперимент

## Что работает

Оставлен один CatBoostRanker с пятью признаками. Его артефакт сохранил историческое имя `catboost_small.cbm`, чтобы не пересоздавать модель; прежний артефакт CatBoost может оставаться в архиве, но в код выдачи не загружается. Вычисляются три списка кандидатов: BM25, гибридный поиск по словам и эмбеддингам и CatBoost, ранжирующий кандидатов гибрида. Это зависимые методы: они используют общие признаки и кандидатов. Вес метода нельзя считать его независимым вкладом или вероятностью покупки.

В каждом списке берутся до 60 позиций; затем применяется взвешенный Reciprocal Rank Fusion:

```text
score(d) = сумма по методам [weight(method) × 61 / (60 + позиция(d, method))]
```

Отсутствие в списке даёт нулевой вклад. `60` — прежняя настройка, в этом эксперименте отдельно не оптимизировалась. Выбор пользователем подсказки может дополнительно изменить итоговый score; такие выборы здесь не размечены. Локальная Gemma разбирает короткие/сложные запросы. Проверенный предмет может давать ограниченный множитель `1 + llm_boost × доля_совпавших_слов`, но в текущем эксперименте выбран **нулевой** коэффициент: вывод разбора не означает изменение порядка. Подробнее — [инструкция по Ollama](../../docs/OLLAMA.md).

## Данные и методика

Файл [ensemble_cases_v2.json](../ensemble_cases_v2.json) содержит 193 искусственных запроса, 45 семейств задач: 120 запросов/28 семейств train, 34/8 validation, 39/9 test. Формулировки одного семейства целиком принадлежат одному разделу. Темы разнообразны: кофейни и франшизы, аренда, налоги, ИП, наём и лояльность, реклама, маркетплейсы, ИИ и другие. Это не полное покрытие данных: размечены 87 разных карточек каталога из 1469, по четыре оценки на запрос; преобладают статьи. Запросы и оценки составлены ассистентом, людьми не проверены. Некоторые формулировки одного семейства наследуют одинаковую разметку, которая может не подходить всем нюансам запроса. Часть прежнего теста уже просматривалась; некоторые карточки могли встречаться в синтетическом обучении CatBoost. Это не независимый слепой тест и не реальные поисковые логи.

Оценка 3 означает прямой ответ, 2 — частично релевантный, 1 — связанный контекст, 0 — нерелевантный. В метриках неразмеченные документы считаются нулём. Поэтому так называемый `precision5_pooled` — доля размеченных как релевантные в первых пяти, а не настоящая Precision@5 для всей выдачи. `mrr60_pooled` — обратная позиция первого известного релевантного результата в первых 60. `ndcg5_pooled` учитывает степени релевантности на первых пяти позициях и нормирует их по размеченным карточкам; из-за неполной разметки он не является достоверным NDCG полного каталога. `judged5` показывает долю результатов первой пятёрки, которые вообще размечены. Сначала вычисляются показатели для запроса, затем средние для семейств, затем одинаковое среднее семейств: семейства с пятью перефразировками не получают больший вес, чем семейства с тремя.

1. Отдельно оценены три компонента. Предварительные веса пропорциональны их NDCG на validation: BM25 0,3216, гибрид 0,3424, CatBoost 0,3360.
2. На validation перебраны 36 комбинаций весов с шагом 0,1, суммой 1 и нижней границей 0,1. Максимизировался pooled NDCG@5. При равенстве — MRR, затем pooled Precision@5 и близость к равным весам. Границы и шаг — инженерный выбор, другие настройки не проверены.
3. После выбора весов на той же validation отдельно перебраны бонусы LLM 0, 0,05, 0,1, 0,2. При равенстве выбирается нулевой. Для применения ненулевого бонуса требуются как минимум пять запросов validation с подтверждённым извлечением и совпадением. Это слабый порог, а не доказательство надёжности.
4. После выбора итоговая конфигурация измерялась на test. Train здесь не используется для нового обучения CatBoost; ранее обученная модель сохранена. Все отдельные результаты и метрики находятся в [report.json](report.json), а каждая комбинация — в [weight_trials.json](weight_trials.json).

## Результаты

| Метод | Validation pooled NDCG@5 | Test pooled NDCG@5 | Test pooled MRR@60 | Test judged@5 |
|---|---:|---:|---:|---:|
| BM25 | 0,4806 | 0,6093 | 0,7280 | 0,1926 |
| Гибрид | 0,5116 | 0,6953 | 0,8069 | 0,2252 |
| CatBoost | 0,5020 | 0,6072 | 0,7016 | 0,2207 |
| Объединение: 0,5 / 0,2 / 0,3 | **0,6109** | 0,6947 | 0,8027 | 0,2326 |

Начальные веса на validation дали pooled NDCG@5 0,5899, подбор сеткой — 0,6109. На test объединение примерно равно гибриду по этим предварительным оценкам, а не лучше его. На validation нулевой LLM-бонус дал 0,6109, а 0,05 / 0,1 / 0,2 — 0,6106 / 0,6033 / 0,5975. Поэтому выбран 0. Только 5 запросов validation оказались пригодны для такого бонуса, так что вывод крайне ограничен. Из всех 193 запросов разбор вернул `ok` на 63, пропущен по маршрутизации на 106, не дал подтверждённых полей на 23 и был недоступен на одном. `ok` проверяет наличие буквальных фрагментов, а не их смысловую правильность.

## Как повторить

Из `05_code` при наличии готовых каталога, векторов, модели CatBoost, библиотек и работающего Ollama:

```bash
PYTHONPATH=src .venv/bin/python scripts/ensemble_experiment.py --with-ollama --install
PYTHONPATH=src .venv/bin/python scripts/evaluate_ollama.py
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v
```

Без `--install` эксперимент не меняет активную конфигурацию. Без `--with-ollama` тестируются только три списка и бонус будет нулевым. `--install` проверяет хеши каталога, векторов и модели перед записью настроек. Перезапустите сервер после установки. Для содержательных выводов нужны независимо размеченные топы нескольких систем, больше запросов для каждого типа материалов, отдельный действительно закрытый набор, реальные запросы и продуктовые показатели после запуска. Синтетический тест сам по себе не измеряет покупки и прибыль.
