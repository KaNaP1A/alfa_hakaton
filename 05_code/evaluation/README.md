Актуальная end-to-end проверка: [аудит](../docs/RANKING_AUDIT_2026-11-12.md), `scripts/audit_ranking.py`. Ниже описан **исторический внутренний retrieval-эксперимент** на 58 запросах; его числа нельзя сравнивать с текущей выдачей после допуска карточек. Для строгой человеческой оценки используйте [инструкцию разметки](../docs/ANNOTATION_GUIDE.md).

## Набор данных

`judgments.json` содержит 58 запросов из 29 семейств: train 36 запросов, validation 10, test 12. Похожие перефразировки одной семьи разделены только вместе. По каждому запросу вручную выбраны 4 оценки: 3 — ответ на задачу, 2 — частично полезно, 0 — не отвечает. Разметка составлена ассистентом по метаданным, не пользователями и не экспертами банка. Её надо проверить; выборка мала и не представляет все запросы.

Разделение защищает от повторения перефразировок, но не гарантирует новых материалов в test: один материал может участвовать в разных семьях. Часть запросов и оценки могут быть спорными. Неизвестные материалы не считаются настоящими отрицательными примерами при обучении. В pooled NDCG неразмеченные результаты условно имеют 0; доля размеченных в первых 5 (`judged_at_5`) показана отдельно. Это заниженная и смещённая оценка, не онлайн-конверсия. Тестовые результаты уже наблюдались при разработке: для окончательных выводов нужен новый слепой тест и независимая разметка.

## Как повторить

Из `05_code`, после импорта и построения embeddings:

```bash
python3 -m venv --system-site-packages .venv
.venv/bin/python -m pip install -r requirements-rank.txt
PYTHONPATH=src .venv/bin/python scripts/experiments.py
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v
```

`results_corrected/weight_trials.json` — 108 первичных комбинаций; `category_trials.json` — ещё 64 комбинации трёх независимых весов категорий; `selected_config.json` — выбранная на validation конфигурация; `report.json` — метрики; `catboost.cbm` — экспериментальная модель. Для воспроизведения нужен именно тот же каталог: идентификаторы и его SHA-256 записаны в наборе и конфигурации. Данные и векторы в Git не включаются. `catboost.cbm` — результат эксперимента, не пользовательские данные.

Сначала выбираем по validation NDCG@5 среди первичной сетки. Затем, удерживая выбранные остальные параметры, отдельно сравниваем веса topics, tags и industries. При равенстве используется сортировка параметров, а не test. После выбора выводятся сравнения на test. Поскольку test уже просмотрен, не считать его новым независимым тестом.

## Значения и обоснование

* BM25 `k1=1.5`, `b=0.75` — исходные стандартные рабочие значения; в этой серии не оптимизировались.
* Поля title, description, topics, tags, industries, body, lessons считаются независимо. Базовые веса: 2, 1, 0.5, 0.5, 0.5, 0.25, 0.75. Это исходная инженерная точка, не установленные оптимумы.
* Проверены title {1,2,4}, общий начальный вес трёх категорий {0,0.5,1,2}, вес тела {0,0.25,0.75}, dense {0.5,1,2}. Отдельно каждая из трёх категорий перебрана среди {0,0.5,1,2}. Сетка ограничена ради воспроизводимости и малого набора, не гарантирует глобальный оптимум. Значения лучшего кандидата — в `selected_config.json`.
* `RRF k=60`, глубина до 60 кандидатов на канал — начальные значения, не оценены в этой серии. Объединяем найденные по тексту и близкие вектора; выбор темы не добавляет отдельные документы, а даёт максимум 25% исходному баллу, умножая эффект на долю совпавших слов. Коэффициент 0.25 пока не подобран на отдельных размеченных сценариях выбора темы.
* Dense-представления делятся на окна по 96 токенов с перекрытием 16: это меньше лимита модели 128 и сохраняет контекст между кусками; числа — инженерные, отдельного подбора длины не было. Для материала используется максимум похожести его карточки, фрагмента статьи и разрешённого урока. Длинные материалы получают больше шансов на случайное совпадение; следует оценить нормализацию.
* CatBoostRanker: YetiRank, 250 деревьев, глубина 4, learning_rate 0.05, seed 42, CPU 2 потока. Это небольшая повторяемая отправная конфигурация; гиперпараметры модели пока не оптимизировали. Признаки — оценки отдельных полей, сходство каждого типа фрагмента, пересечение слов, тип материала, выбранная тема. ID материала/пользователя не используются.

## Наблюдения и ограничения

См. `results_corrected/report.json`. На данном наборе CatBoost хуже базового метода на test; выбранная по validation сетка тоже немного хуже baseline на test. Поэтому в том эксперименте сохранили исходную конфигурацию. Текущий CLI по умолчанию использует экспериментальный ансамбль, гибрид выбирается явно; это не доказательство преимущества ансамбля. Значения не говорят о прибыли или вероятности покупки. Модель обучена только на оценках 4 документов на запрос, а выдача получается из значительно большего каталога. Особые случаи отсутствия ответа и выбор темы требуют отдельной разметки и измерения false positives. No-answer gate пока не обучен.

Полные статьи индексируются только если в исходной таблице одновременно явно `IsPublic=true` и тип `open`; уроки — только прошедшие проверку права и родителей. Это политика метаданных, не подтверждение пользовательских прав. Закрытые и неизвестные материалы не открываются по косвенным признакам. Платные полные тексты не индексируются.
