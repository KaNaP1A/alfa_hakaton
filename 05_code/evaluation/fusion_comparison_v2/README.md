# Сравнение компонентов и весов

Проведён локальный перебор **286 комбинаций весов** с шагом 0,1 для BM25, MiniLM, E5 и CatBoost. Включены все 15 непустых наборов четырёх компонентов; веса неотрицательны и в сумме дают 1. Непрерывное множество вещественных весов перебрать невозможно. [Все варианты и метрики](report.json).

Сначала оценён реальный пул 75 задач с автоматическими оценками, затем 320 задач синтетического dev. В каждом запросе методы сортируют один и тот же заранее заданный пул, сигналы нормируются min-max. Показаны NDCG@5, MRR@5, P@5 и recall по размеченному пулу. Это **диагностика сортировки кандидатов**: действующий поиск ещё отбирает кандидатов и применяет пороги, поэтому результаты не равны конечной пользовательской выдаче и не сравнимы напрямую с прежними 0,381/0,572.

Последний вариант выбран только по validation NDCG@5 до синтетической оценки. На показанном test он уступает отдельным компонентам. Эти результаты нельзя считать доказательством оптимальных весов: validation — лишь 6 задач из 2 семейств, test — 15 задач из 5, все оценки автоматические, оба набора уже были доступны разработке, а validation использовалась ранее при выборе исходной модели. CatBoost уже содержит признаки BM25 и E5. Найденные веса в работающий поиск не установлены.

Смесь также проверена через полный поисковый pipeline с извлечением, правилами и порогами: [результаты](serving_report.json). Сравнивались только запросы, где **все результаты обеих систем** присутствовали в оценённом пуле; неразмеченные результаты не принимались за ноль. Таких оказалось 4/6 validation и 13/15 test. На этих 13 test-задачах: текущий профиль — NDCG@5 **0,4389**, MRR@5 **0,3167**, P@5 **0,0933**; смесь — **0,4215**, **0,2389**, **0,0800** соответственно. Полностью неоценённые запросы исключены из обеих систем, поэтому такой поднабор может быть смещён. Результаты оценены локальной моделью, не людьми, и test ранее просматривался.

После этого все 286 вариантов проверены с правилами конечного pipeline: [полный отчёт](full_serving_grid.json). Для ускорения неизменные сигналы и правила допуска рассчитаны заранее; для каждого запроса результат сопоставлен с настоящим `SearchEngine.search` на текущем профиле и пяти контрольных комбинациях — **450 совпадений из 450**. Скрипт `scripts/evaluate_serving_grid.py` не меняет настройки поиска.

Для сравнения всех 286 вариантов на одинаковых размеченных запросах осталось всего **2 из 6 validation** и **6 из 15 test**; прочие исключены, поскольку хотя бы один вариант вернул неразмеченную карточку. Доля пустых выдач текущего профиля, усреднённая по семействам, на этом общем test-срезе составляет 0,667. На этом очень малом и смещённом срезе NDCG@5 текущего профиля — 0,2101, ранее выбранной смеси — 0,1764. Эти числа показывают ограниченность разметки, а не надёжный рейтинг моделей. Более широкий парный срез для текущего профиля и смеси описан выше.

Исключены термины из реального пула для всех методов. На синтетическом каталоге MiniLM получает название и описание целиком; его реальный индекс устроен иначе. В обоих каталогах сравнение не проверяет потерю нужного материала вне пула, качество порогов и задержку. [Предыдущая сетка с шагом 0,25](../fusion_comparison_v1/README.md).

## Проверка пересечений

После нормализации регистра, «ё» и пунктуации ни один из 172 текстов раскрытого синтетического test не совпал полностью с 800 запросами слабого обучения или 120 ассистентскими train-запросами, доступными при предыдущем эксперименте. Выбранная модель обучалась только на первых 800. Проверка точного текста не исключает перефразировок, общей тематики или пересечения с предобучением encoder.

При этом **8 из 20** закрытых проверок поиска по названию используют реальные карточки, которые встречались среди целей слабого обучения. Это тест поиска в знакомом каталоге, а не оценка переноса на новые материалы. Среди 40 проверок истории просмотра 6 событий относятся к трём таким карточкам; рекомендации после просмотра используют отдельную эвристику.

Для искусственного корпуса генератор использовал одну заданную цель при создании и запроса, и документа, а также поместил синоним в описание положительного документа. Разметка определяется теми же шаблонами. Это делает тест слишком предсказуемым и завышает переносимость результата; само совпадение слов запроса и документа не является доказательством утечки test в обучение. Доступа к данным предобучения E5 нет, поэтому полностью исключить скрытую утечку нельзя. Ранее опубликованный синтетический NDCG нельзя считать надёжной оценкой качества на реальном каталоге.

Есть и пересечение смысла между семействами синтетических dev и test: в dev-семействе 12 цель — «погасить задолженность», а контраст — «взыскать задолженность»; в test-семействе 13 эти действия поменяны местами. Аудитории различаются, но разбиение по ID не даёт полной изоляции смыслов. Все 280 документов, включая документы для test-задач, присутствуют в поисковом индексе при dev-прогоне. Это режим известного каталога, не тест на новые документы. Предыдущее название «закрытый тест» нельзя понимать как полностью независимую проверку.

Запуск из `05_code`: `PYTHONPATH=src HF_HUB_OFFLINE=1 OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 .venv/bin/python scripts/compare_score_fusions.py`. Скрипт не меняет установленный поисковый алгоритм.
