# Единое ранжирование: тесты и выбор весов

## Что объединяется

В интерфейсе теперь один способ поиска. Для одного запроса вычисляются четыре упорядоченных списка:

1. **BM25** — поиск по полям текста.
2. **Гибрид** — BM25 и смысловой поиск, уже объединённые через RRF.
3. **CatBoost** — прежний экспериментальный ranker.
4. **CatBoost-small** — ranker с пятью признаками.

Важно: это зависимые друг от друга компоненты. Гибрид включает BM25, а CatBoost использует те же текстовые и смысловые признаки. Поэтому итоговые веса не являются независимым вкладом четырёх разных источников информации.

## Формула и значения

Сырые значения BM25, cosine и CatBoost имеют разные масштабы. Поэтому сначала берём позиции в каждом списке и вычисляем взвешенный RRF:

```text
final_score(d) = Σᵢ weightᵢ × (k + 1) / (k + rankᵢ(d))
```

Каждый список ограничен первыми 60 материалами; если материала в нём нет, вклад этого метода равен нулю. `k=60` — прежняя стартовая настройка RRF, **здесь отдельно не подбиралась**. `(k+1)` — общий масштаб, не меняет порядок. Метод RRF описан в [исходной работе](https://cormack.uwaterloo.ca/cormacksigir09-rrf.pdf); здесь используются собственные веса.

После объединения явное уточнение пользователя может дать ограниченный дополнительный множитель `1 + 0.25 × покрытие_слов × совпадение_с_уточнением`. Этот множитель взят из предыдущей версии, **в текущем эксперименте не подбирался**: в тестах нет размеченных выборов подсказок. Компоненты сначала получают исходный запрос, и уточнение применяется один раз после объединения. Оценка не является вероятностью покупки или полезности.

Текущие веса:

| Компонент | Вес |
|---|---:|
| BM25 | 0.2 |
| Гибрид | 0.3 |
| CatBoost | 0.1 |
| CatBoost-small | 0.4 |

Они подобраны по неполной синтетической разметке, не являются окончательными и могут переобучаться. У каждой модели принудительно минимум 0.1, чтобы сравнивать именно объединение четырёх методов; варианты с отключением компонентов в этой сетке не изучены. Возможен лучший вариант с нулевым весом. Сами модели здесь не переобучались; признаки и модельные веса описаны в `../large_results/README.md`.

## Данные и методика

В `../ensemble_cases.json` — **116 искусственных формулировок из 29 семейств**, по 4 перефразировки на семейство. 58 взяты из предыдущей ассистентской разметки, ещё 58 написаны для этого теста. Это не реальные логи. Оценены только 4 карточки на запрос: `3` — прямо отвечает, `2` — частично полезна, `1` — связанный контекст, `0` — нерелевантна. Формулировки и метки предварительные; в них возможны ошибки. Разметку желательно перепроверить нескольким людям, добавив больше оценённых кандидатов.

Все перефразировки семейства находятся в одной части: 72 запроса / 18 семейств train, 20 / 5 validation, 24 / 6 test. Train здесь показан для полноты; ранее один CatBoost обучался на части этих запросов. Validation и test в предыдущих экспериментах уже просматривались и использовались при разработке: они **не являются чистой независимой финальной проверкой**.

Сначала оцениваем каждый компонент отдельно. Начальные веса получены нормировкой pooled NDCG@5 на validation. Затем перебраны 84 комбинации с шагом 0.1 и минимальным весом 0.1 на метод; сумма равна 1. Выбирается лучшая validation pooled NDCG@5, при равенстве — MRR@60, затем precision@5 и более равномерные веса. Test не используется в сортировке сетки. `weight_trials.json` содержит все результаты на validation; `report.json` — отдельно результаты каждого компонента и итогового ансамбля для всех 116 запросов по split, начальные веса и top-5 с указанием, какие карточки были оценены.

## Метрики и их ограничения

- **Pooled precision@5** — число известных релевантных (`grade ≥ 2`) в top-5, делённое на 5. Неоценённые условно учитываются как 0. Поскольку на запрос известно всего две релевантные карточки, это ограниченная оценка, а не настоящая доля полезных результатов для человека.
- **Pooled MRR@60** — среднее обратное место первой *известной* релевантной карточки в первых 60. Если выше есть неразмеченная полезная карточка, она не учитывается.
- **Pooled NDCG@5** — метрика порядка по градуированным оценкам 0–3, с неразмеченными на нуле; это смещённая оценка из-за неполной разметки.
- **Judged@5** — доля top-5, которой действительно назначена оценка. Низкое значение означает низкое покрытие разметки, а не плохой результат само по себе. Проблема неполных оценок описана в [Stanford IR Book](https://nlp.stanford.edu/IR-book/pdf/08eval.pdf).

## Результаты

| Метод | Validation pooled NDCG@5 | Test pooled P@5 | Test pooled MRR@60 | Test pooled NDCG@5 | Test judged@5 |
|---|---:|---:|---:|---:|---:|
| BM25 | 0.4470 | 0.1583 | 0.6756 | 0.5720 | 0.1667 |
| Гибрид | 0.4902 | 0.1667 | 0.7282 | 0.6196 | 0.1750 |
| CatBoost | 0.4145 | 0.1417 | 0.6228 | 0.5140 | 0.1583 |
| CatBoost-small | 0.4781 | 0.1917 | 0.7407 | 0.6358 | 0.2250 |
| Комбинация | 0.5911 | 0.1750 | 0.8293 | 0.6815 | 0.2000 |

Показатели комбинации на этой выборке выглядят лучше по MRR и NDCG, но P@5 ниже, чем у CatBoost-small. При **judged@5 = 0.20** и уже наблюдавшемся test эти числа не доказывают улучшения реальной выдачи. Нельзя превращать их в проценты качества, вероятности покупки или ожидаемую прибыль.

## Как повторить

В папке `05_code`, после импорта, создания векторов и установки совместимых моделей:

```bash
PYTHONPATH=src .venv/bin/python scripts/ensemble_experiment.py
PYTHONPATH=src .venv/bin/python scripts/ensemble_experiment.py --install
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v
```

Первая команда обновляет отчёты, но не переключает ранжирование. Вторая дополнительно устанавливает веса в текущее поколение. Перед установкой проверяются хеши каталога, векторов и обеих моделей; если они изменились, эксперимент нужно повторить. Изменение базовой конфигурации retrieval тоже требует повторного подбора и версии реализации.

В локальном UI включите «Режим исследования», чтобы увидеть итоговый скор, веса, позиции методов и выбранное уточнение. На уровне API отдельные режимы сохранены для повторяемости экспериментов; пользователю показывается единая выдача. Требуются обе модели и CatBoost; при отсутствии или несовместимости артефактов система сообщает об ошибке, а не подставляет другие веса.

Следующий шаг — расширить пул оценок по результатам всех методов, перепроверить метки людьми, подготовить новые тематические семейства и непросмотренный test, добавить запросы без ответа и с выбранными подсказками. Только после этого можно надёжнее выбирать веса и оценивать, помогает ли объединение.
