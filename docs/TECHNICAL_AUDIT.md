# Техническая проверка: 16 ноября 2026

## Исправлено

- Исторические записи без подтверждения базовым каталогом больше не появляются
  через дополнительный каталог. Публичная карточка показывается отдельно только
  с допустимым URL источника; синтетическая остаётся помеченной как непроверенная.
- Совпадение по одному названию не переносит внешний URL, вымышленную оферту
  или неподтверждённую карточку на ID бэкапа.
- API отклоняет отметки начала и завершения курса, если доступ не подтверждён.
- Профиль отклоняет повторяющиеся направления и форматы; фронтенд очищает такие
  повторы перед отправкой. Повтор загрузки профиля после сетевой ошибки возвращает
  интерфейс в рабочее состояние.
- Дополнительные возможности рекомендательных адаптеров выражены отдельными
  контрактами. Проверка границ слоёв охватывает вложенные модули и запрещает
  обратные зависимости адаптеров от API и сервисов.
- Для персональных рекомендаций список допустимых ID передаётся модели до
  ограничения выдачи; бэкенд повторно проверяет карточки перед ответом.
- Локальный запуск учитывает изменение версии и весов ранжировщика при сборке
  индекса; обновление runtime-копии модели откатывается при ошибке. Фронтенд
  получил фиксированный lockfile. Описаны архитектура и потоки данных.
- Добавлен CI для бэкенда, ядра алгоритма, фронтенда и запуска. Команды проверены
  локально также на копии без игнорируемых бэкапа и весов; сам GitHub Actions
  начнёт выполняться после публикации изменений.

## Оставшиеся ограничения

- Имеются только снимок бэкапа, публичные метаданные и синтетика. Для реальных
  продаж нужны действующие оферты, валюты, цены, права, платёжные события и
  возвраты. Синтетические модели не доказывают эффективность.
- Механизмы самоотчёта и кликов не образуют полноценную аналитику: нет согласованной
  схемы показов с идентификатором выдачи, A/B-группами и атрибуцией покупок. Без
  них нельзя измерить влияние ранжирования на выручку и удержание.
- Структура слоёв и автоматические проверки не являются полной независимой
  проверкой безопасности и не делают локальный запуск production-сервисом.
  Ограничитель запросов находится в памяти одного процесса; перед развёртыванием
  на нескольких инстансах нужны общая защита, наблюдаемость и проверка доступа.
- Старые экспериментальные файлы и отдельный исследовательский интерфейс
  сохранены для воспроизводимости; основной сайт их не использует. Фронтендовые
  тесты проверяют логику и сборку, но автоматической проверки браузерного интерфейса
  в CI пока нет. Полная проверка реальной модели и PostgreSQL выполняется локально,
  поскольку CI не содержит бэкап и веса.
