# Рабочая структура проекта

Актуальный проект и единственная рекомендуемая рабочая Git-копия — `integrated/`.
Все команды ниже выполняются из её корня. `main` связан с GitHub; локальные изменения
не публикуются сами и видны через `git status`.

```text
integrated/
├── 05_code/           рекомендательный алгоритм, исследования, тесты, своё .venv
├── backend/           FastAPI, базы и интеграция алгоритма, своё .venv
├── frontend/          React-интерфейс для API бэкенда
├── demo_catalog/      отдельный локальный интерфейс смешанного каталога
├── data/              снимок публичных страниц и вымышленные примеры
├── models/recommender/ проверенный комплект модели из Git LFS
├── models/runtime/    локальная запускаемая копия модели, исключена из Git
├── models/sandbox/    тестовые базы и локальные результаты, исключены из Git
└── docs/              спецификации и план развития
```

Рядом с `integrated/` сохранена старая `05_code/`: там остаются исходные базы,
исторические снимки и результаты экспериментов. Они могут содержать персональные или
закрытые данные и в Git не попадают. Старая `.push-algorithm/` содержит собственные
незакоммиченные изменения и тоже сохранена. Корневая `.git/` вне `integrated/` не
содержит коммитов. Старые каталоги не являются полной копией текущего проекта.

Из старой версии перенесены в рабочий репозиторий отсутствовавшие исследовательские
скрипты, тесты и документы — без перезаписи новых файлов. Новые файлы пока локальные;
для их отправки в GitHub нужно отдельно проверить `git status` и создать коммит.

## Запустить демонстрационный сайт

```sh
python3 demo_catalog/server.py --catalog data/demo_catalog.json --port 8767
```

Открыть http://127.0.0.1:8767/. Сайт — отдельный демонстратор, не React-фронтенд и не
модель ранжирования; вымышленные цены помечены. Инструкция: `demo_catalog/README.md`.

## Алгоритм

Окружение находится в `05_code/.venv`. На этой машине оно использует также установленные
системные Python-пакеты; переносить `.venv` на другой компьютер нельзя. После установки
зависимостей по `models/README.md` запустить подготовленную runtime-копию:

```sh
PYTHONPATH=05_code/src HF_HUB_OFFLINE=1 05_code/.venv/bin/python -m alfa_reco serve \
  --output models/runtime/catalog --relevance --no-llm --port 18003
```

Если runtime ещё нет, создайте его по `models/README.md`. Проект хранит модель через
Git LFS; файлы `models/recommender`, `models/runtime` и кэш Git LFS выполняют разные
роли, поэтому их нельзя считать простыми копиями для безопасного удаления. Изменение
пути runtime требует его подготовки заново или корректного `--relocate`.

## Проверки

```sh
cd 05_code
PYTHONPATH=src HF_HUB_OFFLINE=1 .venv/bin/python -m unittest discover -s tests -v
```

В результате организации 297 тестов алгоритма прошли; отдельный запуск модели через новое
окружение вернул 5 результатов на запрос «налоги для ИП». Бэкенд и React-фронтенд имеют
собственные инструкции в их README. Действующие процессы на портах 8080, 18000 и 8767
не останавливались.

## Крупный дубликат

`05_code/artifacts/backend_handoff_NEW 2` был побайтово одинаков с
`05_code/artifacts/backend_handoff_NEW` и перемещён в корзину macOS под именем
`Alfa-hak-backend_handoff_NEW-duplicate` (около 509 МБ). Он восстанавливается из корзины;
место на диске фактически освободится после её очистки. Другие снимки и экспериментальные
артефакты не удалялись: у них могут быть разные пути в манифестах или уникальные данные.

Дополнительно четыре одинаковых файла весов encoder проверены по SHA-256 и заменены
на независимые APFS-клоны файла из `models/recommender`. Пути и содержимое сохранены,
но копии используют общие блоки диска до изменения (copy-on-write); это не жёсткие
ссылки, изменение одной копии не меняет остальные. `du` может показывать размер каждого
файла целиком, даже когда блоки разделяются. Модель в Git LFS и её объектный кэш сохранены.
