# SQL-миграции API

`001_api_state.sql` создаёт только новые служебные таблицы `alfa_api_*`.
Таблицы восстановленного снимка не изменяются и не копируются.
В снимке нет таблицы пользователей сайта: учётные записи API создаются отдельно,
их ID не считаются ID пользователей из `CourseUserBindings`.

Миграции **не применяются** ни при восстановлении дампа, ни при старте API.
`migrate` — отдельный сервис с профилем `tools`; запускайте его только вручную:

```bash
cd backend
docker compose --env-file .env.snapshot --profile tools run --rm migrate
```

`psql` останавливается на первой ошибке; SQL обёрнут в транзакцию.
Версия фиксируется в `alfa_api_schema_migrations`. Повторный запуск первой миграции
не удаляет данные. `CREATE TABLE IF NOT EXISTS` не обновляет отличающиеся столбцы:
для последующих изменений нужны новые SQL-файлы.
