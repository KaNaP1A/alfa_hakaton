# Альфа-Курс — React JSX frontend для FastAPI

Версия адаптирована к **`backend/` в `KaNaP1A/alfa_hakaton`** (публичный контракт `/api/v1`). Она больше НЕ использует `frontend_handoff/mock_server.py` — у того совершенно другой контракт. Сохранена палитра и оформление Альфа-Курса.

## Локальный запуск

В корне исходного репозитория:

```bash
cd backend
uv sync --frozen
uv run alfa-backend seed-demo
uv run uvicorn app:create_app --factory --port 8080 --no-access-log --no-proxy-headers
```

Открыть `http://127.0.0.1:8080/docs`, проверить `/health` и `/ready`. Это **демо-режим**, который не запускает E5/CatBoost.

В папке этого фронтенда:

```bash
cp .env.example .env
npm install
npm run dev
```

Открыть `http://127.0.0.1:5173`. Для Windows можно просто скопировать `.env.example` в `.env`. `VITE_API_PROXY_TARGET` по умолчанию `http://127.0.0.1:8080`. Vite проксирует `/api`, `/health`, `/ready` к FastAPI. Не указывайте URL внутреннего ML-сервиса `:8000`.

Протестировать клиент: `npm test`. Проверить production build: `npm run build` (требуются загруженные npm-зависимости).

## Сценарий проверки

1. Регистрация с логином 3–64 символа (латиница, цифры, `_.-`) и паролем 10–128 символов.
2. Заполнить анкету (категории и цель) — `PUT /api/v1/me/profile`.
3. Проверить `GET /api/v1/search` и подсказки `GET /api/v1/suggest`.
4. Открыть карточку: отправится событие `viewed`. Для курса можно отметить `completed`; это самоотчёт пользователя, не LMS-прогресс.
5. Перейти «Для вас» — `POST /api/v1/recommend` с `{ "generation": "..." }`.
6. Перейти «Мой маршрут» — `POST /api/v1/development-plan` с тем же телом.
7. Выйти и войти тем же логином — профиль и история сохранены в БД.

## Архитектура

- `src/shared/api/client.js` — единственный адаптер HTTP: Bearer, обработка общего конверта ошибок, таймауты.
- `src/features/auth/` — сессия и формы входа/регистрации.
- `src/features/profile/` — профиль сервера, история, события.
- `src/features/onboarding/` — первоначальные интересы и цель.
- `src/features/search/` — поиск и подсказки, выбор подсказки или уточнения.
- `src/features/recommendations/` — персональная выдача.
- `src/features/learning-plan/` — маршрут.
- `src/shared/ui/` — карточки, диалог, состояния.
- `src/app/` — сборка приложения, навигация и связь модулей.

## Контракт и ограничения

- `GET /health` для версии `generation`. Все персональные методы под `/api/v1` и требуют Bearer.
- `/recommend`, `/development-plan` передают **только** `generation`, а профиль и активность сервер берёт из БД.
- История пользователя не создаётся локально. `viewed`, `completed`, `clicked` пишутся через `/me/events`; идентификатор события уникален.
- Для демо выбирайте категорию `business`, чтобы получить материалы из seed-каталога. Выдача может быть пустой.
- Подсказки модели: использовать исходный `q`, `selection_id`, `selection_generation`; подсказки демо: искать по `label`.
- `clarification.options[].token` передаётся как `clarification_token`, текстовое уточнение — `clarification_text`.
- `canonical_url` отображается **только** если бэкенд вернул `access_verified: true` и HTTPS-ссылку; цены только при `price.status: known`.
- При 401 сессия сбрасывается. При 409 и смене поколения пользователь должен обновить данные. Серверное хранение токена в БД; в браузере токен временно сохраняется в `sessionStorage` — для внешнего продакшена нужна отдельная оценка безопасности (XSS, HTTPS, CSP).
- Поля `goal`, `industry`, `experience`, `business_stage`, `preferred_kinds`, `region` сохраняются через профиль, **но пока не влияют на ML-рекомендации**. Анкета собирает только цель и категории; цель используется для отдельного поиска.
- Нет подтверждённой LMS-активности, платежей, refresh-токена, SSR, автоматической синхронизации реального каталога или полноценного E2E с реальной моделью.

## Переход в реальный режим

Бэкендер переключает `ALFA_RECO_MODE=http`, запускает ML на `:8000`, импортирует доверенный каталог той же `generation`, проверяет `/ready` и реальный поиск. Фронтенду **не нужно** менять URL на `:8000`: он по-прежнему обращается к FastAPI на `:8080`.

Связанные исходники: [`backend/api/routes.py`](https://github.com/KaNaP1A/alfa_hakaton/blob/main/backend/api/routes.py), [`backend/domain/responses.py`](https://github.com/KaNaP1A/alfa_hakaton/blob/main/backend/domain/responses.py), [`backend/README.md`](https://github.com/KaNaP1A/alfa_hakaton/blob/main/backend/README.md).


## Стартовый каталог (исправление 15.11)
После входа фронтенд вызывает `GET /health`, `GET /api/v1/me`, `GET /api/v1/me/events` и `GET /api/v1/catalog?limit=12&offset=0`. До поиска показывается каталог; фильтры и «Показать ещё» используют `kind` и `offset`. Поиск из строки остаётся отдельным `/api/v1/search`, а «Вернуться к каталогу» возвращает исходный список. Опрос доступен из основного экрана и рекомендаций.

В демо `seed-demo` импортирует 4 вымышленных материала, один недоступен обычному пользователю: в стартовом каталоге ожидаются **3 карточки** (если не меняли права и данные). Чтобы показать настоящие материалы Альфа-Курса, требуется доверенный импорт каталога; фронтенд их не генерирует.


## Автоматическое обновление интересов

Во вкладке «Для вас» выбор направлений и доступных подтем сохраняется автоматически. Сохранение происходит через `PUT /api/v1/me/profile`, затем новый список загружается через `POST /api/v1/recommend` (в теле только `generation`). Во время сохранения старые карточки скрываются, чтобы не воспринимались как подборка по новым темам. Изменить цель и направления также можно через анкету.

Короткая задержка 180 мс объединяет быстрые клики; запросы `PUT` профиля выполняются последовательно. Перед выходом ожидается завершение начатого сохранения. При ошибке интерфейс возвращает сохранённый выбор и показывает сообщение, чтобы не создавать ложное ощущение успешного обновления.

Код разделён: `Recommendations.jsx` — кнопки интересов, `useAutoInterests.js` — состояние выбора, `interestAutosave.js` — очередь записи на сервер. Проверка: `npm test`.

## Оформление и доступность

Интерфейс использует локальный шрифт Onest и компоненты для входа, каталога,
рекомендаций и маршрута. Решения и происхождение ассетов описаны в [DESIGN.md](DESIGN.md).
Предусмотрены видимый фокус, адаптация к узким экранам и `prefers-reduced-motion`;
диалоги поддерживают закрытие клавишей Escape и возврат фокуса.

```bash
npm test              # Контракты API, логика клиента и проверки интерфейса
npm run test:ui       # Формы, поиск, карточки и диалоги
npm run review:render # HTML-снимки с искусственными тестовыми данными
```
